# P8-2 앱 이미지 · Docker Compose 전체 실행 · api 2대 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `docker compose --profile app up -d --build` 한 번으로 인프라 + 모의 은행 + 게이트웨이 1대 + **api 2대** + nginx 를 띄우고, 2대가 되면 깨지는 "인스턴스 안의 상태"(기본 모드 · 하루 배치 · 대사 파일 · 종료)를 처리한 뒤, CI 스모크와 실험 E1 ~ E5 로 가용성 · 정합성을 확인한다. 처리량 증가는 목표가 아니다.

**Architecture:** 루트 `Dockerfile` 하나가 멀티 스테이지로 세 앱(`api` · `bank-gateway` · `mock-bank`)을 만든다 — Gradle 빌드 단계 한 번, Boot jar 는 레이어로 풀어 4층 복사, 실행은 JRE Alpine · 비root · exec 형식 `ENTRYPOINT`. Compose `app` 프로필이 nginx(8000, 라운드 로빈 · 연결 단계 실패만 다음 서버) → `api-1` · `api-2`(`mode=http`) → `bank-gateway` → `mock-bank` 를 내부망에 띄우고, 대사 파일은 공유 볼륨, 하루 배치 2개는 ShedLock(JDBC, DB 시각)으로 한 대만 돈다.

**Tech Stack:** Kotlin 2.3.21 · Java 21 · Spring Boot 4.1.1 (Spring 7.0.9) · ShedLock 7.10.1 (`shedlock-spring` · `shedlock-provider-jdbc-template`) · Flyway (MySQL 8.4) · Testcontainers 2.0.5 · Docker BuildKit (`# syntax=docker/dockerfile:1.7`) · `eclipse-temurin:21-jdk` / `21-jre-alpine` · Docker Compose v2 (로컬 v5.6.0) · `nginx:1.27-alpine` · k6 2.3.0 · GitHub Actions (`docker/setup-buildx-action@v4` · `docker/build-push-action@v7`) · Git Bash 스크립트

**Spec:** `docs/superpowers/specs/2026-11-11-p8-2-compose-design.md` (커밋 7e4ff53)

## Global Constraints

- 주석 · 문서 · 커밋 메시지는 한국어. 커밋 형식 `type(p8-2): 한국어 요약`, 끝 줄 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **돈 불변식은 건드리지 않는다**: 접수 때 차감 · 잔고 = 원장 합 · 같은 거래번호 은행 송신 1번 · "안 보냄만 다시 보낸다, 모르면 묻는다". 이 단계의 코드 변경은 설정 · 하루 배치 락 · 배포물뿐이다. 아웃박스 발행(0.5초) · 정리 작업(10초)에는 락을 걸지 않는다 (걸면 한 대만 일한다 — 스펙 §2).
- PC 에 여는 포트는 **nginx `8000` 하나**. `app` 프로필 서비스 중 `ports:` 가 있는 것은 nginx 뿐이다 (게이트웨이 · 모의 은행 · api 는 내부망 전용).
- 이미지에 비밀값이 없다: `.dockerignore` 에 `infra/.env`, Dockerfile 에 비밀번호 `ENV` · `ARG` 없음. 비밀은 실행 때 Compose 가 `infra/.env` 에서 환경변수로 넣는다.
- nginx 는 이미 보낸 요청을 다른 서버로 다시 보내지 않는다: `proxy_next_upstream error timeout` 만, `non_idempotent` 금지.
- 시간 순서: api graceful 단계 `20s` < Compose `stop_grace_period: 30s`. api 의 게이트웨이 응답 시간 초과 `5s` < nginx `proxy_read_timeout 10s`.
- `bank.gateway.mode` 기본은 `http` (api · api-reactive). 테스트 공통 기반 · 측정 스크립트 · 측정용 실행 구성은 `direct` 를 명시한다.
- Kafka 파티션 3 · api 당 `concurrency: 3` 은 바꾸지 않는다 (2대면 컨슈머 6 중 3은 논다 — 드러내기만).
- 건드리지도 스테이징하지도 않는다: `.run/2. API (8080).run.xml`(사용자의 커밋하지 않은 수정), `postman/`, `infra/.env`.
- 개발 DB(로컬 MySQL)에 쓰는 행은 측정 · 스모크 사용자 **`load-p82-*`** 만이고 끝나면 지운다. 그 밖에는 읽기만.
- `git stash` 금지. 스테이징은 **파일 이름으로** (`git add -A` · `git add .` 금지). 커밋 뒤 `git status --short` 에 `.run/2. API (8080).run.xml` 이 ` M` 으로 남아 있는지 확인한다.
- 버전은 정확히: ShedLock `7.10.1`, `eclipse-temurin:21-jdk` · `eclipse-temurin:21-jre-alpine`, `nginx:1.27-alpine`, `grafana/k6:2.3.0`(기존), `docker/setup-buildx-action@v4` · `docker/build-push-action@v7`.
- 셸 스크립트는 Git Bash(로컬) · bash(CI) 둘 다에서 돈다. `*.sh` · `*.yml` 은 LF (`.gitattributes`).
- 테스트 수: 기준은 P8-1 끝의 608개(건너뜀 2). Task 1 +4, Task 2 +5, Task 3 +5 → 622. 기준 수가 다르면 증가분만 맞으면 된다.

## 스펙과 다르게 정한 것 (근거)

1. **CI 비밀번호**: 스펙 §7-2 "CI 는 `infra/.env.example` 을 쓴다". 그러나 예시의 `MYSQL_PASSWORD=local-dev-only` 는 `application.yml` 의 기본값(`${MYSQL_PASSWORD:local-dev-only}`)이기도 해서 "이미지에 비밀번호 값이 없음" 검사가 항상 걸린다. → CI 는 `.env.example` 을 `infra/.env` 로 복사하고 두 비밀번호만 실행마다 임의 값으로 바꾼다. 스모크는 `.env.example` 과 같은 값은 검사에서 뺀다 (로컬).
2. **`X-Upstream`** 의 `$upstream_addr` 는 컨테이너 이름이 아니라 `IP:포트` 다 → 스모크 · 실험은 "서로 다른 값 2개" + `/actuator/info` 의 `instance`(`api-1` · `api-2`)로 확인한다.
3. **E5 주기**: 스펙 "1분마다로 5분". `lockAtLeastFor = PT1M` 이 주기와 같으면 `lock_until(= locked_at + 60s)` 이 다음 회차 시각보다 조금 늦어 **두 대 모두 건너뛰는 회차**가 생긴다 → **2분마다 10분(5회차)**.
4. **Dockerfile 캐시 마운트**: 스펙의 `--mount=type=cache,target=/root/.gradle` 은 바로 위 `RUN ./gradlew --version` 층이 받아 둔 래퍼 배포판(`/root/.gradle/wrapper`)을 가린다 → 캐시 마운트는 `/root/.gradle/caches` 에만. `gradlew` 는 `sh ./gradlew` 로 부른다 (Windows 빌드 컨텍스트의 실행 비트에 기대지 않게).
5. **환경변수 이름**: 스펙 `DAILY_RECON_FILE_DIR` → 표준형 `DAILYRECON_FILEDIR` (예전형도 동작하지만 표준형으로 통일).
6. **`BankGatewayProperties` 코드 기본값**도 `http` 로 바꾸고 `matchIfMissing` 을 http 빈으로 옮긴다 (스펙 §8 은 yml 만 적었지만 §3-7 "코드 기본 direct + 컨테이너만 http" 를 버린 대안으로 적었다 — yml · 데이터 클래스 · 조건이 같은 값을 보게).
7. **`shedlock` 시각 컬럼 `TIMESTAMP(3)`** 은 스펙대로 두되, 저장소 규칙(KST `DATETIME`)의 예외로 `docs/database.md` 에 적는다 (값은 UTC — ShedLock 이 DB 시각 `UTC_TIMESTAMP(3)` 로 쓴다). 컨트롤러가 `DATETIME(3)` 으로 바꾸고 싶으면 Task 3 Step 3 · 5 의 두 곳(마이그레이션 · `DatabaseSetupTest` 기대값)만 바꾸면 된다 — 비교식이 같은 DB 시각을 쓰므로 동작은 같다.
8. 측정용 실행 구성 **`5. API (부하 측정)`** 에도 `--bank.gateway.mode=direct` 를 넣는다 (스펙 §8 "측정은 direct 명시" 의 범위).

```kotlin
/**
 * 하루 배치 락 (P8-2, ADR-0016). api 가 여러 대가 되면 @Scheduled 가 대수만큼 돈다 — 일마감 대사 · 보존 배치만 한 대에서 돌게 한다.
 * 락은 1차 방어다: 같은 날짜 잡은 Spring Batch 잡 인스턴스가, 대사 이슈는 UNIQUE (recon_date, type, ref_key) 가 두 번째로 막는다.
 * 발행기 · 정리 작업에는 걸지 않는다 (걸면 한 대만 일한다 — 이미 SKIP LOCKED · 조건부 UPDATE 로 행 단위 안전, 스펙 §2).
 *
 * - usingDbTime: 락 시각을 DB 시각(UTC_TIMESTAMP)으로 쓰고 비교한다 → 서버끼리 시계가 달라도 같다.
 * - locked_by = info.instance (Compose 의 INFO_INSTANCE = api-1 · api-2, 없으면 local) — 누가 돌았는지 shedlock 표 · 로그로 맞춰 본다.
 * - 방식은 PROXY_METHOD(기본): @SchedulerLock 메서드를 가진 빈을 CGLIB 프록시로 감싼다 → 스케줄러 클래스와 run() 은 open 이어야 한다.
 */
@Configuration(proxyBeanMethods = false)
@EnableSchedulerLock(defaultLockAtMostFor = "PT30M")
class SchedulerLockConfiguration {

    @Bean
    fun lockProvider(dataSource: DataSource, @Value("\${info.instance:local}") instance: String): LockProvider =
        JdbcTemplateLockProvider(
            JdbcTemplateLockProvider.Configuration.builder()
                .withJdbcTemplate(JdbcTemplate(dataSource))
                .usingDbTime()
                .withLockedByValue(instance)
                .build(),
        )
}
```

  ```markdown
  ### 4-10. `shedlock` — 하루 배치 락 (P8-2)
  | 컬럼 | 타입 | 뜻 |
  |---|---|---|
  | `name` | `VARCHAR(64)` PK | 락 이름 = 배치 하나: `daily-recon` · `data-retention` |
  | `lock_until` | `TIMESTAMP(3)` | 이 시각까지 다른 서버는 못 잡는다. 잡을 때 = 지금 + lockAtMostFor(대사 50분 · 보존 30분), 끝나면 = max(시작 + lockAtLeastFor 1분, 지금) |
  | `locked_at` | `TIMESTAMP(3)` | 마지막으로 잡은 시각 |
  | `locked_by` | `VARCHAR(255)` | 잡은 서버 = `info.instance` (Compose `INFO_INSTANCE` = api-1 · api-2, IntelliJ 는 `local`) |

  - 값은 **UTC** 다 (ShedLock `usingDbTime` 이 `UTC_TIMESTAMP(3)` 로 쓰고 비교 — 서버 시계 차이와 무관). KST 로 읽으려면 +9시간.
  - 잡기: `INSERT IGNORE` (행이 없을 때) 또는 `UPDATE … WHERE name = ? AND lock_until <= UTC_TIMESTAMP(3)` — 영향 행이 1이면 잡은 것. 행은 지우지 않고 다시 쓴다.
  - 죽은 서버의 락은 `lock_until` 이 지나면 다른 서버가 가져간다. 그래서 lockAtMostFor 는 실제 실행 시간보다 넉넉히, 다음 회차 간격보다 짧게 (근거: `docs/perf/p8-2-compose.md` 의 배치 실행 시간).
  - TIMESTAMP 를 쓴 이유: ShedLock 의 MySQL 정의 그대로 (스펙 §6). 2038년 한계는 락 시각(지금 + 최대 50분)에만 걸린다.
  ```

```dockerfile
RUN --mount=type=cache,id=gradle-caches,target=/root/.gradle/caches,sharing=locked \

FROM eclipse-temurin:21-jre-alpine AS runtime-base
# /data/bank-files: 모의 은행이 쓰고 api 가 읽는 대사 파일 자리. 이미지에서 app 소유로 만들어 두면 처음 붙는 이름 있는 볼륨이 이 소유자를 물려받는다
RUN addgroup -S app && adduser -S app -G app \
 && mkdir -p /data/bank-files && chown -R app:app /data
# 로그 · Spring Batch 메타 시각 · 모의 은행 파일 날짜가 KST (JVM 이 TZ 를 읽는다 — 앱 코드는 시간대를 명시해 이 값에 기대지 않는다)
```

```bash
#!/usr/bin/env bash
# P8-2 앱 컨테이너 스모크 (스펙 §7-2). Compose app 프로필이 떠 있을 때 nginx(:8000) 만으로 확인한다:
#   1) 1원인증 요청 → 모의 은행 로그의 적요 코드 → 확인 → VERIFIED
#   2) 충전 → 출금(Idempotency-Key) → COMPLETED        3) 같은 키로 다시 → 같은 출금 id
#   4) 요청 20번이 api-1 · api-2 둘 다로 (X-Upstream 두 값, /actuator/info 의 instance 두 값)
#   5) 게이트웨이 health UP (컨테이너 안에서), 게이트웨이 · 모의 은행 · api 포트는 PC 에 열리지 않음
#   6) 컨테이너 사용자 ≠ root, 이미지(층 기록 · 파일)에 infra/.env 의 비밀번호 값이 없음
#   7) (CI 만) 대사 파일 디렉터리 바인딩 — 모의 은행이 쓴 파일을 api 가 읽는다 (DB 에 2000-01-01 대사 행이 남아 로컬 개발 DB 에서는 하지 않는다)
# 사용 (Git Bash · Linux): bash infra/app-smoke.sh
#   먼저: docker compose -f infra/docker-compose.yml --env-file infra/.env --profile app up -d --build --wait
# 개발 DB 에는 사용자 load-p82-smoke-<시각> 의 행만 쓰고 끝에서 지운다 (측정 행 규칙).
set -euo pipefail
export MSYS_NO_PATHCONV=1   # Git Bash 가 /data/... 같은 인자를 Windows 경로로 바꾸지 않게
cd "$(dirname "$0")"

ENV_FILE=.env
[ -f "$ENV_FILE" ] || ENV_FILE=.env.example
dc() { docker compose -f docker-compose.yml --env-file "$ENV_FILE" --profile app "$@"; }
# 비밀번호는 mysql 컨테이너가 이미 가진 환경변수로만 (PC 명령행에 나오지 않게 — load/run.sh 와 같은 방식)
sql() { dc exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" exec mysql -u"$MYSQL_USER" "$MYSQL_DATABASE" --default-character-set=utf8mb4 -N'; }
ok() { printf '  \033[32mOK\033[0m %s\n' "$1"; }
fail() { printf '  \033[31mFAIL\033[0m %s\n' "$1" >&2; exit 1; }
port_open() { timeout 1 bash -c "exec 3<>/dev/tcp/127.0.0.1/$1" 2>/dev/null; }
json() { { grep -o "\"$1\":\"[^\"]*\"" || true; } | head -1 | cut -d'"' -f4; }   # 평평한 JSON 에서 문자열 값 하나 (없으면 빈 줄 — pipefail 로 여기서 끝나지 않게)
code() { tail -1 <<<"$1"; }   # curl -w '\n%{http_code}' 결과의 상태 코드
body() { sed '$d' <<<"$1"; }

BASE=http://localhost:8000
USER_ID="load-p82-smoke-$(date +%s)"
ACCOUNT=1002123456789
PW=$(mktemp)

cleanup() {
  rm -f "$PW"
  sql >/dev/null 2>&1 <<SQL || echo "  (정리 실패 — 사용자 $USER_ID 의 행을 손으로 지운다: load/compose/cleanup.sql 과 같은 순서)" >&2
DELETE o FROM outbox_event o JOIN transfer t ON t.id = o.aggregate_id WHERE t.user_id = '$USER_ID';
DELETE FROM wallet_ledger WHERE user_id = '$USER_ID';
DELETE FROM transfer WHERE user_id = '$USER_ID';
DELETE FROM account_verification WHERE user_id = '$USER_ID';
DELETE FROM wallet WHERE user_id = '$USER_ID';
SQL
}
trap cleanup EXIT

post() {   # $1 = 경로, $2 = JSON 본문(표준입력으로 — 한글이 셸 인자 변환을 거치지 않게), 나머지 = curl 인자
  local path=$1 data=$2; shift 2
  printf '%s' "$data" | curl -s -w '\n%{http_code}' -X POST "$BASE$path" -H 'Content-Type: application/json' -H "X-User-Id: $USER_ID" "$@" --data-binary @-
}

echo "[0/7] 준비"
for p in 8080 8082 9090; do
  if port_open "$p"; then echo "  경고: PC 포트 $p 가 쓰이고 있다 — IntelliJ 의 API · 게이트웨이 · 모의 은행을 끈다 (같은 DB · 같은 컨슈머 그룹, 스펙 §5-5)" >&2; fi
done
for s in mock-bank bank-gateway api-1 api-2 nginx; do

done
ok "app 프로필 5개 healthy"

echo "[1/7] 1원인증"
R=$(post /api/v1/account-verifications "{\"bankCode\":\"090\",\"accountNo\":\"$ACCOUNT\",\"holderName\":\"홍길동\"}")
[ "$(code "$R")" = 201 ] || fail "1원인증 요청 $(code "$R"): $(body "$R")"
VID=$(body "$R" | json id)
VCODE=$(dc logs --no-color --no-log-prefix mock-bank 2>/dev/null | grep -a "$ACCOUNT" | grep -ao "BT[0-9]\{4\}" | tail -1 | cut -c3- || true)
[ -n "$VCODE" ] || fail "모의 은행 로그에서 적요 코드(BT + 4자리)를 찾지 못했다"
R=$(post "/api/v1/account-verifications/$VID/confirm" "{\"code\":\"$VCODE\"}")
[ "$(body "$R" | json status)" = VERIFIED ] || fail "확인 $(code "$R"): $(body "$R")"
ok "1원인증 → VERIFIED (적요 코드는 모의 은행 로그에서)"

echo "[2/7] 충전 → 출금 → COMPLETED"
R=$(post /api/v1/wallet/deposits '{"amount":10000}')
[ "$(code "$R")" = 200 ] || fail "충전 $(code "$R"): $(body "$R")"
KEY="smoke-$USER_ID"
TRANSFER="{\"bankCode\":\"090\",\"accountNo\":\"$ACCOUNT\",\"amount\":1000,\"memo\":\"smoke\"}"
R=$(post /api/v1/transfers "$TRANSFER" -H "Idempotency-Key: $KEY")
[ "$(code "$R")" = 202 ] || fail "출금 접수 $(code "$R"): $(body "$R")"

S=
for _ in $(seq 60); do
  S=$(curl -s "$BASE/api/v1/transfers/$TID" -H "X-User-Id: $USER_ID" | json status)
  [ "$S" = COMPLETED ] && break
  sleep 1
done
[ "$S" = COMPLETED ] || fail "60초 안에 COMPLETED 가 아니다 (지금 $S)"
ok "출금 $TID → COMPLETED"

echo "[3/7] 같은 멱등키로 다시"
R=$(post /api/v1/transfers "$TRANSFER" -H "Idempotency-Key: $KEY")

echo "[4/7] 분배"

echo "[6/7] 비root · 이미지 비밀"

pw_values() { grep -E '^(MYSQL_PASSWORD|MYSQL_ROOT_PASSWORD)=' "$1" | cut -d= -f2- | tr -d '\r' | grep -v '^$' || true; }
```

```javascript
// P8-2 E3 · E4: nginx(:80) 를 거쳐 출금을 일정한 속도로 (열린 모델 — api 한 대가 내려가도 요청은 계속 온다).
// 사용자 load-p82-u001 ~ u020 (load/compose/seed.sql). 실패(5xx · 연결 실패)는 같은 멱등키로 1초 뒤 최대 3번 다시 보낸다 —
// 클라이언트가 결과를 모를 때 할 일이고, 서버는 같은 키를 한 번만 접수한다 (ADR-0004). 그래서 "최종 접수된 키 수 = 출금 행 수" 여야 한다.
// 환경변수는 load/compose/run.sh 가 넘긴다: BASE_URL(http://nginx:80) RUN RATE(초당, 20) DURATION(60s)
import http from 'k6/http';
import { sleep } from 'k6';
import { Counter } from 'k6/metrics';
import exec from 'k6/execution';

const BASE_URL = __ENV.BASE_URL || 'http://nginx:80';
const RUN = __ENV.RUN || 'local';
const RATE = Number(__ENV.RATE || 20);
const DURATION = __ENV.DURATION || '60s';
const BODY = JSON.stringify({ bankCode: '090', accountNo: '1002123456789', amount: 1, memo: 'p82' });

const first202 = new Counter('first_202');        // 첫 시도에 접수
const first5xx = new Counter('first_5xx');        // 첫 시도 5xx (nginx 502 포함)
const first502 = new Counter('first_502');        // 첫 시도 502 — 보낸 뒤 api 가 끊겼다 (nginx 는 다시 보내지 않는다)
const firstNet = new Counter('first_neterr');     // 첫 시도 연결 실패 · 시간 초과 (상태 0)
const retried = new Counter('retried_requests');  // 같은 키로 다시 보낸 요청 수
const accepted = new Counter('accepted_keys');    // 최종 202 · 200 을 받은 키 수 = DB 출금 행 수여야 한다
const gaveUp = new Counter('gave_up_keys');       // 다시 보내도 실패한 키 (DB 에 있을 수도 있다 — run.sh 가 출금 행과 비교한다)

export const options = {
  discardResponseBodies: true,
  scenarios: {
    steady: { executor: 'constant-arrival-rate', rate: RATE, timeUnit: '1s', duration: DURATION, preAllocatedVUs: 40, maxVUs: 200 },
  },
};

export default function () {
  const it = exec.scenario.iterationInTest;
  const user = `load-p82-u${String((it % 20) + 1).padStart(3, '0')}`;
  const key = `p82-${RUN}-${it}`;   // 64자 이내 ASCII
  const params = { headers: { 'Content-Type': 'application/json', 'X-User-Id': user, 'Idempotency-Key': key }, timeout: '15s' };

  let res = http.post(`${BASE_URL}/api/v1/transfers`, BODY, params);
  if (res.status === 202) first202.add(1);
  if (res.status >= 500) first5xx.add(1);
  if (res.status === 502) first502.add(1);
  if (res.status === 0) firstNet.add(1);

  for (let i = 0; i < 3 && res.status !== 202 && res.status !== 200; i++) {
    if (res.status !== 0 && res.status < 500) break;   // 4xx 는 다시 보내도 같다
    retried.add(1);
    sleep(1);
    res = http.post(`${BASE_URL}/api/v1/transfers`, BODY, params);
  }
  if (res.status === 202 || res.status === 200) accepted.add(1);
  else gaveUp.add(1);
}

export function handleSummary(data) {
  const count = (m) => (data.metrics[m] ? data.metrics[m].values.count : 0);
  const out = {
    run: RUN, rate: RATE, duration: DURATION,
    iterations: count('iterations'), first_202: count('first_202'), first_5xx: count('first_5xx'), first_502: count('first_502'),
    first_neterr: count('first_neterr'), retried_requests: count('retried_requests'), accepted_keys: count('accepted_keys'), gave_up_keys: count('gave_up_keys'),
    p95_ms: data.metrics.http_req_duration.values['p(95)'], max_ms: data.metrics.http_req_duration.values.max,
  };
  return { stdout: `${JSON.stringify(out)}\n`, [`/out/p8-2/${RUN}.k6.json`]: JSON.stringify(out, null, 2) };
}
```

```bash
for s in mock-bank bank-gateway api-1 api-2 nginx; do
  id=$(dc --profile app ps -q "$s")
  [ -n "$id" ] || die "$s 가 없다 — 먼저 --profile app up -d --build --wait"
  [ "$(docker inspect -f '{{.State.Health.Status}}' "$id")" = healthy ] || die "$s 가 healthy 가 아니다"
done
OTHER=$(sql <<<"SELECT COUNT(*) FROM transfer WHERE status IN ('RECEIVED','SENDING','UNKNOWN') AND NOT ($USERS)" | tr -d '\r')
[ "$OTHER" = 0 ] || echo "[$RUN] 경고: 측정 사용자 밖에 처리 중인 출금 $OTHER 건 — 컨테이너 api 가 함께 처리한다 (측정 확인은 측정 사용자만 본다)" >&2

# --- 2. 시드 ---
sql < load/compose/cleanup.sql
sql < load/compose/seed.sql
T0=$(date -u +%Y-%m-%dT%H:%M:%SZ)

# --- 3. 부하 + 동작 ---
echo "[$RUN] k6 ${RATE}건/s × $DURATION → nginx:80, 동작 $ACTION @ ${ACTION_AT}s"
dc --profile load run --rm -e BASE_URL=http://nginx:80 -e RUN="$RUN" -e RATE="$RATE" -e DURATION="$DURATION" \
  k6 run --quiet /scripts/compose/withdraw.js > "$WORK/k6.out" 2>&1 &
K6_PID=$!
T_ACTION=null; AUTO_RESTART=null
if [ "$ACTION" != steady ]; then
  sleep "$ACTION_AT"
  T_ACTION="\"$(date -u +%Y-%m-%dT%H:%M:%S.%3NZ)\""
  case "$ACTION" in
    restart) dc --profile app restart api-1 >/dev/null ;;                     # SIGTERM → graceful(단계당 최대 20초) → 다시 기동
    kill)    docker kill "$(dc --profile app ps -q api-1)" >/dev/null ;;      # SIGKILL — 처리 중 요청 · 커밋 안 한 오프셋이 그대로 끊긴다
  esac
fi
wait "$K6_PID" || die "k6 가 실패했다 — $WORK/k6.out"
[ -f "$K6J" ] || die "k6 요약이 없다 — $WORK/k6.out"
if [ "$ACTION" = kill ]; then
  # restart: unless-stopped 가 kill 뒤에 다시 띄웠나 (Docker 는 사람이 멈춘 컨테이너를 다시 띄우지 않는다 — kill 이 그 경우인지 기록)
  st=$(docker inspect -f '{{.State.Status}}' "$(dc --profile app ps -aq api-1)")
  if [ "$st" = running ]; then AUTO_RESTART=true; else AUTO_RESTART=false; fi
fi
dc --profile app up -d --no-build --wait api-1 >/dev/null   # 내려가 있으면 올린다 — 정합성은 두 대로 끝까지 처리한 뒤 본다
# 다시 뜬 api-1 의 IP 가 바뀌었을 수 있다 — nginx 는 기동 때 한 번만 이름을 푼다. 부하는 끝났으므로 다음 회차 · E2 를 위해 다시 풀게 한다
[ "$ACTION" = steady ] || dc --profile app restart nginx >/dev/null

# --- 4. 완료 대기 (재배달 · SENDING 정리 · 결과조회까지) ---
P=-1; SETTLE_S=0
for SETTLE_S in $(seq "$SETTLE"); do
  P=$(sql <<<"SELECT COUNT(*) FROM transfer WHERE $USERS AND status <> 'COMPLETED'" | tr -d '\r')
  [ "$P" = 0 ] && break
  sleep 1
done

# --- 5. 정확성 ---
declare -A C
while IFS=$'\t' read -r k v; do C[$k]=$v; done < <(sql < load/compose/verify.sql | tr -d '\r')
k6v() { grep -o "\"$1\": *[0-9.]*" "$K6J" | head -1 | sed 's/.*: *//'; }
ACCEPTED=$(k6v accepted_keys)
# 은행 거래 기록 한 줄 = "D" + 거래번호 20자 + … (load/consumer 와 같다). 측정 출금의 거래번호마다 정확히 한 줄이어야 한다
sql < load/compose/refs.sql | tr -d '\r' | sort > "$WORK/refs.txt"
{ dc --profile app exec -T mock-bank sh -c 'cat /data/bank-files/journal/*.log 2>/dev/null' || true; } | grep -a '^D' | cut -c2-21 | sort > "$WORK/journal-refs.txt" || true
JOURNAL_MISSING=$(comm -23 "$WORK/refs.txt" <(sort -u "$WORK/journal-refs.txt") | wc -l | tr -d ' ')
JOURNAL_DUP=$({ grep -xF -f "$WORK/refs.txt" "$WORK/journal-refs.txt" || true; } | uniq -d | wc -l | tr -d ' ')

# --- 6. 로그: nginx 5xx · 오류, 리밸런스 ---
dc --profile app logs --no-color --no-log-prefix --since "$T0" nginx > "$WORK/nginx.log" 2>&1 || true
dc --profile app logs --no-color --timestamps --since "$T0" api-1 api-2 > "$WORK/api.log" 2>&1 || true
grep -E "partitions (assigned|revoked)|Adding newly assigned partitions|Revoke previously assigned partitions" "$WORK/api.log" > "$WORK/rebalance.txt" || true
grep -E "\[(error|warn)\].*upstream" "$WORK/nginx.log" > "$WORK/nginx-errors.txt" || true
NGINX_5XX=$(awk '$2 ~ /^5/ && $4 == "/api/v1/transfers"' "$WORK/nginx.log" | wc -l | tr -d ' ')

num() { if [[ "${1:-}" =~ ^[0-9]+(\.[0-9]+)?$ ]]; then echo "$1"; else echo null; fi; }
cat > "$OUT" <<JSON
{"run":"$RUN","action":"$ACTION","rate":$RATE,"duration":"$DURATION","action_at_s":$ACTION_AT,"t0":"$T0","t_action":$T_ACTION,
 "auto_restart_after_kill":$AUTO_RESTART,"settle_s":$SETTLE_S,
 "first_202":$(num "$(k6v first_202)"),"first_5xx":$(num "$(k6v first_5xx)"),"first_502":$(num "$(k6v first_502)"),"first_neterr":$(num "$(k6v first_neterr)"),
 "retried_requests":$(num "$(k6v retried_requests)"),"accepted_keys":$(num "$ACCEPTED"),"gave_up_keys":$(num "$(k6v gave_up_keys)"),
 "p95_ms":$(num "$(k6v p95_ms)"),"nginx_5xx":$NGINX_5XX,
 "transfers":$(num "${C[transfers]:-}"),"not_completed":$(num "${C[not_completed]:-}"),"refunds":$(num "${C[refunds]:-}"),
 "negative_balance":$(num "${C[negative_balance]:-}"),"balance_ne_ledger":$(num "${C[balance_ne_ledger]:-}"),
 "transfer_ne_withdraw":$(num "${C[transfer_ne_withdraw]:-}"),"unpublished_outbox":$(num "${C[unpublished_outbox]:-}"),
 "journal_missing":$JOURNAL_MISSING,"journal_dup":$JOURNAL_DUP,"rebalance_lines":$(wc -l < "$WORK/rebalance.txt" | tr -d ' ')}
JSON
cp "$WORK/rebalance.txt" "$OUT_DIR/$RUN.rebalance.txt"
cp "$WORK/nginx-errors.txt" "$OUT_DIR/$RUN.nginx-errors.txt"

FAILS=()
[ "${C[not_completed]:-x}" = 0 ] || FAILS+=("COMPLETED 아님 ${C[not_completed]:-?} (대기 ${SETTLE_S}초)")
for k in refunds negative_balance balance_ne_ledger transfer_ne_withdraw unpublished_outbox; do
  [ "${C[$k]:-x}" = 0 ] || FAILS+=("$k ${C[$k]:-?}")
done
[ "${C[transfers]:-x}" = "$ACCEPTED" ] || FAILS+=("출금 행 ${C[transfers]:-?} ≠ 접수된 키 $ACCEPTED")
[ "$JOURNAL_MISSING" = 0 ] || FAILS+=("은행 기록에 없는 출금 $JOURNAL_MISSING")
[ "$JOURNAL_DUP" = 0 ] || FAILS+=("은행에 두 번 간 거래번호 $JOURNAL_DUP")
if [ ${#FAILS[@]} -gt 0 ]; then
  mv -f "$OUT" "$OUT.invalid"
  die "정확성 확인 실패 — ${FAILS[*]} ($OUT.invalid, 작업 파일 $WORK)"
fi
# 5xx 는 판정이 아니라 결과다 (스펙: 재시작이면 0 이어야 한다 — 아니면 문서에 원인을 적는다)
if [ "$ACTION" = restart ] && [ "$(k6v first_5xx)" != 0 ]; then echo "[$RUN] 주의: 재시작인데 첫 시도 5xx $(k6v first_5xx) — nginx-errors · api 로그로 원인을 본다" >&2; fi
echo "[$RUN] 통과 — $OUT"
cat "$OUT"
```
