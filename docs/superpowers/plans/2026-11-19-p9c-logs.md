# P9c 로그 모으기 — Grafana Alloy · Loki 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** kind 의 `bank-transfer` namespace 모든 Pod 로그를 노드마다 하나인 Grafana Alloy 가 `/var/log/pods` 에서 읽어 Loki 에 모으고, 보내기 직전 계좌번호 · 1원인증 코드 · 금액을 가리며, Grafana 에서 지표 → trace → 로그를 클릭으로 오가게 한 뒤, 실험 L1 ~ L7 로 수집 지연 · 비용 · 잃는 줄 · 로그 알림 · 가리기를 잰다.

**Architecture:** 앱은 표준 출력에만 쓴다 (Loki 를 모른다 — 결정 F10). kind 에서만 api · 게이트웨이 콘솔을 Spring Boot ECS JSON 으로 바꿔 level · traceId 를 정규식 없이 꺼낸다. Alloy DaemonSet 의 처리(`pipeline.alloy`, 모듈 하나)는 **꺼내기(level · trace_id) → 메타데이터 · 라벨 → 가리기** 순서이고, 같은 모듈을 CI 가 표본 파일에 실제로 돌려 가리기를 증명한다. Loki 는 단일 바이너리 · emptyDir · 보관 2일 · ruler(로그 알림 `ErrorLogSurge` 하나 → 기존 Alertmanager). 앱 쪽은 사용자 id · 멱등키를 로그에서 빼고(첫 겹), 게이트웨이가 은행 호출마다 trace 문맥에서 한 줄을 남겨 traceId → 게이트웨이 줄 → 거래번호 → 모의 은행 통장 줄로 잇는다.

**Tech Stack:** Kotlin 2.3 · Java 21 · Spring Boot 4.1.1 (structured logging ECS) · Micrometer Tracing 1.7.1 · Hibernate 7 · Redisson 4.8.0 · Grafana Loki 3.7.9 · Grafana Alloy v1.21.3 · Grafana 12.0.0 · Prometheus v3.5.0 · Alertmanager v0.28.1 · Tempo 2.10.10 · kind · kustomize · Bash · k6 · Python 3 (대시보드 검사)

**Spec:** `docs/superpowers/specs/2026-11-19-p9c-logs-design.md` (구속력 있음 — 결정 F1 ~ F10 · 실험 L1 ~ L7 · 성공 기준 §1 은 사용자가 정했다. 이 계획이 스펙과 다르게 정한 것은 맨 끝 "계획에서 정한 것", 스펙 §14 에도 같은 목록)

## Global Constraints

스펙 결정 (§2):
- F1: 범위 = `bank-transfer` namespace 전체 Pod + 로그 ↔ trace 잇기. monitoring · kube-system · Envoy 로그는 모으지 않는다.
- F2: 수집 = Grafana Alloy **DaemonSet** (노드마다 1개, 제어 노드 포함 3개)이 `/var/log/pods` 를 읽는다.
- F3: 저장 = Loki 3.7.9 단일 바이너리 (monitoring namespace, 제어 노드 고정, emptyDir, 보관 2일), 접속은 port-forward 만 (3100).
- F4: 형식 = **kind 에서만** api · 게이트웨이 구조화 로그(JSON, ECS). 로컬 · IntelliJ · Compose 는 텍스트 그대로 (`infra/docker-compose.yml` · `infra/app-smoke.sh` 를 바꾸지 않는다).
- F5: 라벨 = `namespace` · `app` · `container` 만. `pod` · `node` · `level` · `trace_id` 는 구조화 메타데이터.
- F6: 민감 정보 = 이중 방어 — ① 앱이 남기지 않는다 ② Alloy 가 보내기 직전 모든 줄을 가린다 ③ Loki 금지 패턴 0건을 스모크 · 실험으로 증명. 모의 은행 콘솔의 통장 줄은 그대로 (Loki 사본만 가린다).
- F7: 잇기 = Loki 파생 필드(`trace_id` → Tempo) + Tempo `tracesToLogsV2`(traceId 로 Loki 질의).
- F8: 대시보드 ① 출금 흐름에 4행 "로그" (서비스 · 레벨별 양 + api · 게이트웨이 ERROR · WARN 패널).
- F9: 로그 알림은 `ErrorLogSurge` 하나 — Loki ruler → 기존 Alertmanager, `source=logs`, `BankDisconnected` · `GatewayNoLeader` 동안 억제. 임계값은 L6 정상 상태로 정한다.
- F10: 수집이 실패해도 앱은 그대로 — 앱은 표준 출력에만 쓴다.

버전 · 실행 환경:
- 앱 스택은 그대로: Kotlin 2.3 · Java 21 · Spring Boot 4.1.1.
- 이미지 버전은 `infra/k8s/versions.env` 한 곳: `LOKI_VERSION=3.7.9` · `ALLOY_VERSION=v1.21.3`. 매니페스트는 태그 없는 이름, `apply_overlay` 가 덮는다. **kind 노드가 새 이미지를 처음 받기(up.sh) 전에 사용자 허락을 받는다** (계획 단계의 확인용 pull 허락과 별개).
- kind 만 구조화 로그(JSON) · 로그 수집. 로컬 · IntelliJ · Compose 는 바꾸지 않는다.
- 관측 UI 는 `kubectl port-forward` 로만. Loki · Tempo · Prometheus 질의는 `kubectl exec deploy/prometheus -- wget` (PC 포트를 열지 않음, `jq` 없이 grep · awk).
- Loki 는 제어 노드 고정: `nodeSelector: {bank-transfer/role: infra}` + control-plane toleration. Alloy 는 DaemonSet + control-plane toleration.
- CI `k8s-smoke` 20분 제한 그대로 (이미지 두 개 · DaemonSet 대기가 늘어난다 — 위험 R6).
- 돈 정확성 판정(`load/k8s/run.sh` 의 판정 · 스모크 [2] · [3])은 바꾸지 않는다 — 모든 실험 회차에서 같은 판정이 통과해야 한다.

비밀 · 저장소 규칙:
- 비밀번호 · 키를 파일이나 출력에 남기지 않는다. **Grafana 관리자 비밀번호는 절대 출력하지 않는다.** MySQL root 비밀번호는 mysql Pod 안의 환경변수로만 쓴다 (`sql()` 과 같은 방식).
- 커밋 메시지 끝 줄은 정확히 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- 파일을 **이름으로** stage 한다 (`git add -A` · `git add .` 금지). `.run/2. API (8080).run.xml` 은 일부러 수정된 상태(` M`) — **절대 stage 하지 않는다.** `git stash` 금지. `infra/.env` · Postman 앱이 다시 쓴 파일은 커밋하지 않는다.
- 전 직장 코드 · 민감정보(IP · 계정 · 키)를 저장소에 넣지 않는다. 실험 원자료에 로그 원문을 커밋하지 않는다 (숫자 · Loki 지표 질의 결과만).

스크립트 · 문서 규칙:
- 스크립트는 Git Bash · Linux 둘 다에서 돈다. 새 yaml · sh · alloy · 표본 txt 는 LF (`.gitattributes` — Task 5).
- `.gitignore` 가 `*.log` 를 무시한다 → 표본 · 원자료 로그는 `.txt`.
- `kubectl logs | grep -q` 파이프는 pipefail + SIGPIPE 로 거짓 실패한다 → 변수로 받아 here-string 으로 grep (P9b 계획에서 정한 것 28).
- LogQL 은 ASCII 로 쓴다 — `lib.sh urlenc` 은 한글을 바이트로 바꾸지 못한다. '원' 은 `\x{C6D0}`.
- 주석 · 테스트 이름 · 문서는 한국어 (기존 스타일). 테스트는 kotlin.test + 백틱 한국어 이름. 테스트 JVM 은 `-Duser.timezone=UTC`.

Postman v3 규칙 (`postman/collections/bank-transfer/`):
- 컬렉션 변수는 문자열 (`"0"`, `""`). 숫자는 스크립트에서 `Number(...)`.
- `url` 의 질의 문자열과 `queryParams` 목록이 정확히 같아야 한다.
- 수집 지연은 테스트 스크립트에서 `pm.execution.setNextRequest(pm.info.requestName)` 로 제한된 횟수만 다시 묻는다.

```kotlin
            // 사용자 id 도, 예외 메시지 · 스택도 싣지 않는다 — Redisson 시간 초과 메시지는 명령 인자(락 이름 = lock:wallet:<사용자 id>)를 싣는다 (P9c 결정 F6 ①)
            log.error("redis unavailable for wallet lock, rejecting (fail-closed): {}", e.javaClass.name)
            throw StoreConflict.WalletBusy(userId)
        } catch (e: InterruptedException) {
            Thread.currentThread().interrupt()
            throw StoreConflict.WalletBusy(userId)
        }
        if (!acquired) {
            // 핫스팟에서는 흔한 결과라 INFO (부하 측정은 WARN 으로 돌린다). 같은 줄의 traceId 로 요청을 찾는다 (P9c)
            log.info("wallet lock not acquired within {}, answering WALLET_BUSY", waitTime)
            throw StoreConflict.WalletBusy(userId)
        }
        try {
            // 접수 트랜잭션은 이 안에서 시작 · 커밋된다 → 아래 unlock 은 커밋 뒤다 (JpaTransferStore 가 바깥 트랜잭션을 거부해 보장한다)
            return transaction()
        } finally {
            unlockQuietly(lock)
        }
    }

    override fun withdraw(userId: String, transferId: UUID, amount: Long, at: Instant): Boolean =
        inner.withdraw(userId, transferId, amount, at)

    /** 해제 실패는 결과를 바꾸지 않는다. 로그에는 예외 클래스 이름만 — 메시지에 락 이름(사용자 id)이 실릴 수 있다 (P9c). */
    private fun unlockQuietly(lock: RLock) {
        try {
            lock.unlock()
        } catch (e: RedisException) {
            log.error("failed to unlock wallet lock after commit; it expires by lease: {}", e.javaClass.name)
        } catch (e: IllegalMonitorStateException) {
            // 연장이 끊겨(긴 GC 멈춤 등) 이미 만료됐다. 안쪽이 조건부 UPDATE 라 잔고는 틀리지 않았다 (ADR-0009)
            log.error("wallet lock expired before unlock: {}", e.javaClass.name)
        } catch (e: RuntimeException) {
            // 알려진 두 경우 말고도 finally 에서 던지면 커밋된 접수가 500 이 되거나 트랜잭션의 진짜 예외를 가린다 → 로그만 남기고 삼킨다
            log.error("unexpected failure while unlocking wallet lock; it expires by lease: {}", e.javaClass.name)
        }
    }
```

```kotlin
            reference ?: "-",
```

```bash
# --- P9c 로그 ---
# Loki HTTP API — Prometheus Pod 의 busybox wget 으로 (PC 포트를 열지 않는다). LogQL 은 ASCII 로 쓴다 (urlenc 이 한글을 바이트로 못 바꾼다 — '원' 은 \x{C6D0})
loki_get() { km exec deploy/prometheus -- wget -qO- "http://loki.monitoring.svc.cluster.local:3100$1"; }
# 줄 수 = sum(count_over_time(<$1> [<$2>s])) 즉시 질의, $3 = 시각(epoch 초, 없으면 지금) → 범위 (시각 − $2, 시각].
# 질의 실패면 빈 값 (0 으로 위장하지 않는다), 줄이 없으면 0 (Loki 는 빈 결과를 준다)
loki_count() {
  local out
  out=$({ loki_get "/loki/api/v1/query?query=$(urlenc "sum(count_over_time($1 [$2s]))")${3:+&time=$3}" 2>/dev/null || true; } | tr -d '\r')
  grep -q '"status":"success"' <<<"$out" || return 0
  { grep -o '"value":\[[^]]*\]' <<<"$out" || echo '"value":[0,"0"]'; } | head -1 | sed -E 's/.*,"([^"]*)"\]$/\1/'
}
```

```alloy
declare "bank_transfer" {
	argument "forward_to" {
		comment = "가린 줄을 받을 곳 (loki.write 또는 loki.echo)"
	}

	loki.process "logs" {
		forward_to = argument.forward_to.value

		// kind(containerd) 로그 파일 한 줄 = "<시각> <stdout|stderr> <F|P> <본문>" — 줄 시각은 이 시각, 잘린(P) 줄은 이어 붙인다
		stage.cri { }

		// ① JSON (kind 의 api · 게이트웨이 — Spring Boot ECS): log.level · traceId(MDC)
		stage.match {
			selector = `{namespace="bank-transfer"} |~ "^\\{"`

			stage.json {
				expressions = {level = "log.level", trace_id = "traceId"}
			}
		}

		// ① 텍스트 (모의 은행 · Kafka · MySQL · Redis, 구조화 로그를 끈 api · 게이트웨이): 머리의 수준 낱말 · Spring 상관 [traceId-spanId]
		stage.match {
			selector = `{namespace="bank-transfer"} !~ "^\\{"`

			stage.regex {
				expression = `(?:^|[\s\[])(?P<level>TRACE|DEBUG|INFO|WARN|ERROR|FATAL)(?:[\s\]]|$)`
			}

			stage.regex {
				expression = `\[(?P<trace_id>[0-9a-f]{32})-[0-9a-f]{16}\]`
			}
		}

		// ② pod · node · level · trace_id 는 구조화 메타데이터 (라벨이면 값마다 스트림이 생긴다).
		//    라벨은 namespace · app · container 셋 — loki.source.file 이 붙이는 filename 도 여기서 버린다
		stage.structured_metadata {
			values = {pod = "", node = "", level = "", trace_id = ""}
		}

		stage.label_keep {
			values = ["namespace", "app", "container"]
		}

		// ③ 가리기 (결정 F6 ②, 스펙 §5-3) — 모든 줄, 보내기 직전.
		// 계좌: 영문 · 숫자에 붙지 않은 10 ~ 14자리 숫자 → 끝 4자리만 남기고 같은 길이의 *. 거래번호(T + 날짜 + 영숫자) · traceId 의 숫자 덩어리는 영문에 붙어 그대로.

		// Go 정규식은 앞뒤 보기가 없어 경계 글자를 같이 먹는다 → "A B" 처럼 붙은 두 번째가 첫 판에서 빠진다. 같은 규칙을 두 번 (가린 값은 숫자 4개라 다시 안 걸린다)
		stage.replace {
			expression = `(?:^|\\[nrtbf]|\\u[0-9A-Fa-f]{4}|[^0-9A-Za-z])([0-9]{6,10})[0-9]{4}(?:[^0-9A-Za-z]|$)`
			replace    = `{{ repeat (len .Value) "*" }}`
		}

		stage.replace {
			expression = `(?:^|\\[nrtbf]|\\u[0-9A-Fa-f]{4}|[^0-9A-Za-z])([0-9]{6,10})[0-9]{4}(?:[^0-9A-Za-z]|$)`
			replace    = `{{ repeat (len .Value) "*" }}`
		}

		stage.replace {
```

```bash
p9c_res_sample() {
  local lc lr ips ip c r ac=0 ar=0
  lc=$(p9c_metric http://loki.monitoring.svc.cluster.local:3100/metrics process_cpu_seconds_total)
  lr=$(p9c_metric http://loki.monitoring.svc.cluster.local:3100/metrics process_resident_memory_bytes)

  done

}
p9c_res_loop() { while :; do p9c_res_sample >> "$WORK/res.txt"; sleep 10; done; }
# $1 ~ $2 (epoch 초) 의 평균 CPU(코어) · 최대 RSS(MiB) → "loki_cpu loki_rss_mb alloy_cpu alloy_rss_mb" (재시작으로 누적값이 줄면 null)
p9c_res_summary() {
  awk -v a="$1" -v b="$2" '$1 >= a && $1 <= b && $2 != "NaN" {
      if (!n++) { t0 = $1; l0 = $2; c0 = $4 }
      t1 = $1; l1 = $2; c1 = $4
      if ($3 + 0 > lr) lr = $3 + 0
      if ($5 + 0 > ar) ar = $5 + 0
    }
    END {
      if (n < 2 || t1 <= t0) { print "null null null null"; exit }
      lc = (l1 - l0) / (t1 - t0); ac = (c1 - c0) / (t1 - t0)
      printf "%s %.0f %s %.0f\n", (lc < 0 ? "null" : sprintf("%.3f", lc)), lr / 1048576, (ac < 0 ? "null" : sprintf("%.3f", ac)), ar / 1048576
    }' "$WORK/res.txt" 2>/dev/null || echo "null null null null"
}

p9c_l1_loop() {
  local pod i t_w found end=$(( $(date +%s) + DURATION_S ))
  pod=$(live_pods api | awk 'NF {print $1; exit}')
  for (( i = 1; i <= L1_SAMPLES; i++ )); do

      printf '%s %s null exec_failed\n' "$i" "$(date +%s%3N)" >> "$WORK/l1.txt"; sleep 2; continue
    fi
    t_w=$(date +%s%3N); found=null

      if [ "$(loki_count "{namespace=\"bank-transfer\", app=\"api\"} |= \"p9c-l1 $RUN $i end\"" 300)" = 1 ]; then found=$(date +%s%3N); break; fi

    done

    sleep 1
  done
}

    END {
      if (!n) { printf "0 null null %d\n", miss + 0; exit }
      for (i = 1; i <= n; i++) for (j = i + 1; j <= n; j++) if (v[j] < v[i]) { t = v[i]; v[i] = v[j]; v[j] = t }
      printf "%d %d %d %d\n", n, v[int((n - 1) * 0.5) + 1], v[int((n - 1) * 0.95) + 1], miss + 0
    }' "$WORK/l1.txt" 2>/dev/null || echo "0 null null 0"
}

# --- L6 ② 1원인증 저장 실패 주입 ---
# 비밀번호는 mysql Pod 가 이미 가진 환경변수로만 (명령행 · 출력에 나오지 않게 — lib.sh sql() 과 같은 방식). 트리거 생성은 binlog 때문에 root 로
sql_root() { k exec -i mysql-0 -- sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot "$MYSQL_DATABASE" -N'; }
p9c_fault_on() {
  sql_root <<'SQL'
DROP TRIGGER IF EXISTS p9c_fault_verification;
CREATE TRIGGER p9c_fault_verification BEFORE INSERT ON account_verification FOR EACH ROW
  SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'p9c fault injection (L6)';
SQL
}
p9c_fault_off() { sql_root <<<"DROP TRIGGER IF EXISTS p9c_fault_verification;" >/dev/null 2>&1 || true; }
# $1 초 동안 VERIFY_EVERY_S 마다 1원인증 요청 (모의 은행 예금주 홍길동 — 성명조회 · 1원은 통과하고 저장에서 500 이 기대값). "epoch_ms 코드" 줄
p9c_verify_probes() {
  local until=$(( $(date +%s) + $1 )) code
  while [ "$(date +%s)" -lt "$until" ]; do
    code=$(printf '%s' '{"bankCode":"090","accountNo":"1002123456789","holderName":"홍길동"}' \
      | curl -s -o /dev/null -w '%{http_code}' -m 20 -X POST http://127.0.0.1:8000/api/v1/account-verifications \
          -H 'Content-Type: application/json' -H 'X-User-Id: load-p82-u001' --data-binary @- || true)
    printf '%s %s\n' "$(date +%s%3N)" "${code:-000}" >> "$WORK/errfault-probes.txt"
    sleep "$VERIFY_EVERY_S"
  done
}

# --- L6 ③ 억제 ---
# BankDisconnected 가 울리면 시험 ErrorLogSurge(60초 뒤 저절로 끝남 — 은행 복구 전)를 Alertmanager 에 넣고, 15초 뒤 그 알림 상태를 남긴다
p9c_inhibit_probe() {

    --post-data="[{\"labels\":{\"alertname\":\"ErrorLogSurge\",\"app\":\"api\",\"severity\":\"warning\",\"source\":\"logs\",\"p9c_probe\":\"$RUN\"},\"annotations\":{\"summary\":\"p9c L6 inhibition probe\"},\"endsAt\":\"$ends\"}]" \

# --- 원자료 ---
# 기대 줄 수에 닿거나 60초가 지나면 마지막 값 (수집 · 재시도 지연을 기다린다). $1 선택자, $2 범위 초, $3 기대, $4 시각
p9c_loki_settle() {
  local i v=
  for (( i = 0; i < 12; i++ )); do
    v=$(loki_count "$1" "$2" "${4:-}")
    if [[ "$v" =~ ^[0-9]+$ ]] && [ "$v" -ge "$3" ]; then break; fi
    sleep 5
  done
  echo "${v:-null}"
}
# 살아 있는 Pod: (T0, 지금−30초] 의 kubectl logs 줄 수 vs Loki 줄 수 → "kubectl loki" (Loki 범위 (시작, 끝] 과 맞춘다 — 초 단위 문자열 비교)
p9c_loss_live() {
  local pod=$1 t0_s end_s from to k_n l_n
  t0_s=$(date -u -d "$T0" +%s); end_s=$(( $(date +%s) - 30 ))
  from=$(date -u -d "@$t0_s" +%Y-%m-%dT%H:%M:%S); to=$(date -u -d "@$end_s" +%Y-%m-%dT%H:%M:%S)
  k_n=$(k logs "$pod" -c api --timestamps --since-time="$T0" 2>/dev/null | awk -v a="$from" -v b="$to" '{ t = substr($1, 1, 19) } t >= a && t < b' | wc -l | tr -d ' ')
  l_n=$(p9c_loki_settle "{namespace=\"bank-transfer\", app=\"api\"} | pod=\"$pod\"" $(( end_s - t0_s )) "$k_n" "$end_s")
  echo "$k_n $l_n"
}
# 5분 ERROR 수의 최대 (T0 ~ 지금, 30초 간격, 모든 app 중). $2 = 원자료 이름
p9c_err5m_max() {

  { grep -o '\[[0-9.]*,"[0-9.]*"\]' "$OUT_DIR/$RUN.loki-$2.json" || true; } | tr -d '[]"' | awk -F, '{ if ($2 + 0 > m) m = $2 + 0 } END { printf "%d", m + 0 }'
}
# 동작 뒤 5분 ERROR 수(규칙 식)가 처음 N 을 넘은 시각 (동작 시각 기준 초, 5초 간격) 또는 null
p9c_cross_s() {
  local q="sum by (app) (count_over_time($P9C_SURGE [5m]))" ta_s=$(( TA_MS / 1000 ))
  { loki_get "/loki/api/v1/query_range?query=$(urlenc "$q")&start=$ta_s&end=$(date +%s)&step=5" 2>/dev/null || true; } | tr -d '\r' > "$OUT_DIR/$RUN.loki-surge-cross.json"
  { grep -o '\[[0-9.]*,"[0-9.]*"\]' "$OUT_DIR/$RUN.loki-surge-cross.json" || true; } | tr -d '[]"' \
    | awk -F, -v n="$P9C_N" -v ta="$ta_s" '$2 + 0 > n { t = $1 - ta; if (best == "" || t < best) best = t } END { if (best == "") print "null"; else printf "%.0f\n", best }'

# alert-sink 원자료에서 알림 $1 의 상태 $2(firing|resolved) 첫 도착 epoch_ms (동작 뒤) — 웹훅 본문 첫 "status" = 묶음 상태
p9c_sink_first() {

  { grep -a "\"alertname\":\"$1\"" "$OUT_DIR/$RUN.alert-sink.txt" || true; } | while read -r ts body; do

  done | awk -v t="$TA_MS" '$1 >= t' | sort -n | head -1
}
# app 별 초당 값 JSON: $1 = sum by (app) 질의, $2 = 시각 → {"api":1.23,...} (DURATION_S 로 나눔)
p9c_by_app() {

}

p9c_capture() {

      done
```

## 계획에서 정한 것 (스펙이 비었거나 코드 · 라이브러리와 달랐던 곳)

1. **ECS 키 확인 · 필드 지정 없음** — Boot 4.1.1 속성 `logging.structured.format.console=ecs`. 줄은 중첩 객체: `log.level` · `log.logger` · `error.{type,message,stack_trace}`, MDC 는 맨 위 `traceId` · `spanId`, `service.name` 은 `spring.application.name` 이 자동으로 채운다 (스펙 §3 "필요하면 지정" → 지정하지 않는다, 환경 필드는 없다). Alloy 는 `log.level` · `traceId` 를 읽는다. 계약 테스트는 별도 JVM (로깅 설정이 JVM 전역이라 공유 테스트 컨텍스트를 JSON 으로 바꾸지 않게).
2. **처리를 Alloy 모듈 하나로 (`declare` + `import.file`)** — 수집 설정(`config.alloy`)과 CI 표본 설정(`check.alloy`)이 같은 `pipeline.alloy` 를 import 한다. 스펙 §8 "가능하면 Alloy 가리기를 표본 줄로 실제 돌려 본다" → 된다: check.sh [6/6] 이 `alloy run` 10초 + `loki.echo` 출력으로 라벨 · 금지 패턴 · trace_id · level 을 단언한다.
3. **가리기 식** — 계좌 `(?:^|\\[nrtbf]|\\u[0-9A-Fa-f]{4}|[^0-9A-Za-z])([0-9]{6,10})[0-9]{4}(?:[^0-9A-Za-z]|$)` → 앞부분을 같은 길이의 `*`. 영문 · 숫자에 붙은 숫자열은 건드리지 않는다 (거래번호 `T` + 날짜 + 영숫자 13자는 10자리 이상 숫자가 영문에 붙어 나올 수 있다 · traceId). JSON 이스케이프(`\n` `\t` … `\uXXXX`) 바로 뒤도 경계 — ECS 예외 메시지 · stack_trace 의 줄바꿈 · 탭 뒤 계좌 (Task 5 리뷰에서 고침, 금지 패턴도 같은 경계, 스펙 §14-10). Go 정규식은 앞뒤 보기가 없어 붙어 있는 두 계좌 중 하나가 첫 판에서 빠진다 → **같은 규칙 두 번**. 금액 `([0-9][0-9,]*)원` → `***원`, 코드 `BT([0-9]{4})` → `BT****`. 과한 가리기: `1원인증` → `***원인증`, Kafka 스냅숏 id 의 10자리 조각, epoch 13자리 (표본으로 확인, R2).
4. **금지 패턴 LogQL** = 세 규칙의 가리지 않은 모양 하나의 정규식: `` |~ `(^|\\[nrtbf]|\\u[0-9A-Fa-f]{4}|[^0-9A-Za-z])[0-9]{10,14}([^0-9A-Za-z]|$)|BT[0-9]{4}|[0-9]\x{C6D0}` `` — '원' 은 `\x{C6D0}` (URL 에 한글을 싣지 않는다 — `urlenc` 은 ASCII 만). 양성 대조(콘솔 원본 · 가린 모양 > 0)를 같이 본다.
5. **Loki 의 자동 라벨 끄기** — 3.7 은 `service_name` 라벨 · `detected_level` 메타데이터를 스스로 붙인다 → `discover_service_name: []` · `discover_log_levels: false` (결정 F5 의 라벨 셋). `loki.source.file` 의 `filename` 라벨은 `stage.label_keep` 이 버린다.
6. **규칙 파일 자리 · 검사 방법** — ConfigMap 을 `/etc/loki/rules/fake` (auth 끔 테넌트) 에 마운트. Loki 이미지에 lint 도구가 없어 check.sh 가 Loki 를 잠깐 띄워 `/prometheus/api/v1/rules`(틀리면 그룹 0개)와 `/loki/api/v1/format_query`(대시보드 · 규칙 LogQL)로 검사한다. 설정은 `-verify-config`.
7. **`ErrorLogSurge` 식에서 Spring Kafka DLT 발행 줄을 뺀다** (`!= "DeadLetterPublishingRecovererFactory"`) — P9b 원자료: 은행 2분 끊김에 api ERROR 742 · 771줄이 전부 이 로거이고 재접속 26초 뒤까지 이어진다. 5분 창 · `for: 2m` 이면 `BankDisconnected` 가 풀린 뒤 울려 억제 밖이다 (스펙 기준 6 을 못 지킨다). DLT 는 지표 알림 `TransferDeadLettered` 가 맡는다 (F9 원칙 "로그 알림은 지표로 못 잡는 것만"). 억제 규칙은 그대로 둔다 (그 밖의 ERROR 몫). 결과적으로 은행 끊김 중 실제 ErrorLogSurge 는 울리지 않을 것이라 L6 ③ 은 **시험 알림을 넣어** 억제를 확인한다 (21).
8. **N = 10 시작값, L6 ① 로 확정** — kind 정상 상태 ERROR 원천은 일마감 대사 파일 없음(Spring Batch `AbstractStep`, 대사 회차마다 Pod 당 1줄, 01 ~ 06시)뿐, steady 회차는 0. 규칙: N = max(10, 정상 5분 최대 × 3). 바뀌면 `rules.yml` · `p9c.sh P9C_N` 을 같이.
9. **L6 ② 장애 = 1원인증 저장 실패** (MySQL 트리거 `p9c_fault_verification` 이 `account_verification` INSERT 를 거부) — 요청마다 api ERROR `unexpected error` + 500, 출금 20건/s 대비 1원인증 5초마다 1건(≈ 1%)이라 `ApiHigh5xx`(5% · 2분)가 울리지 않는다 = 지표로 못 잡는 오류. 출금 돈 흐름은 그대로. 다른 ERROR 자리는 kind 에서 안 나거나(redis 전략 · 텔레그램 · 대사 불일치) 이미 지표 알림이 있거나(DLT · 은행 끊김) 일부러 만들기 어렵다 (정리 작업 한 건 오류) — "ERROR 를 남기는 자리" 표. 은행에는 1원이 간다 (판정과 무관 — 출금 거래번호만 대조). 트리거는 root 로 (binlog), 비밀번호는 Pod 환경변수로만.
10. **게이트웨이 은행 호출 한 줄 추가** (스펙 §3 에 없음) — 정상 출금에서 게이트웨이는 trace 안에서 로그를 한 줄도 쓰지 않는다 → 기준 2 "traceId 로 게이트웨이 로그" 를 못 맞춘다. `withClient` 완료 때 `bank call type= outcome= reason= tranNo= reference= ms=` INFO 한 줄을 `bank.request` 구간 문맥(`tracer.withSpan`)에서 남긴다 (완료 콜백은 은행 Netty 스레드라 문맥이 없다). 계좌 · 금액 · 예금주 · 적요는 싣지 않는다.
11. **모의 은행 줄은 `bank.tran_no` 가 아니라 거래번호(`transfer.reference`)로** — 통장 줄의 `거래번호=` 는 이용기관 거래번호다 (스펙 §1 기준 2 의 `bank.tran_no` 표현을 바로잡음). 경로: traceId → 게이트웨이 줄의 `reference=` → 모의 은행 통장 줄.
12. **사용자 id 빼기 범위 넓힘** — 스펙의 지갑 3곳 + `Transfer.toString`(정리 작업 WARN · ERROR 3곳이 찍는다 — 사용자 id · 금액) 에서 사용자 id · 금액을 뺀다. Redisson 4.8.0 의 시간 초과 예외 메시지는 명령 인자(락 이름 `lock:wallet:<사용자 id>`)를 싣는다 → `RedisWalletDebit` 의 ERROR 는 예외 클래스 이름만 (스택을 잃는 대가 — 지표 · 클래스 이름으로 충분).
13. **Hibernate 제약 위반 로그 끄기** — Hibernate 7 의 `org.hibernate.orm.jdbc.error` 가 WARN 으로 `Duplicate entry '<사용자 id>-<Idempotency-Key>'` 를 찍는다 (테스트 출력으로 확인). 저장소가 도메인 예외로 바꿔 처리하므로 api `application.yml` 에서 이 로거를 ERROR 로 (모든 환경 — kind 만의 문제가 아니다). 매핑 안 된 SQL 오류는 그대로 `ApiExceptionHandler` 의 ERROR(스택 포함)로 남는다.
14. **Alloy 권한 = Role (ClusterRole 아님)** — 발견이 `bank-transfer` namespace 만 보고 노드 정보를 쓰지 않으므로 그 namespace 의 Pod 읽기 Role 이면 된다 (스펙 §4 "ClusterRole(노드 · Pod 읽기)" 를 바꿈 — Prometheus 와 같은 모양, 최소 권한). 노드 이름은 `spec.nodeName` 필드 선택자(`NODE_NAME` 환경변수).
15. **Alloy 는 root · capability 없음** — kind 노드 로그 파일이 `root:root 0640` 이라 root 로 돌고 `drop: [ALL]` (같은 소유자라 읽힌다 — 컨테이너로 확인). 스모크 [7] "비root" 는 앱 3개만이라 그대로. `readOnlyRootFilesystem` 은 확인하지 않아 두지 않는다.
16. **자원** — Alloy 표본 실행 RSS ≈ 203MiB → 요청 128Mi · 상한 512Mi (스펙 "Tempo 와 비슷하게" 보다 크다), Loki 128Mi · 512Mi. L2 로 확인.
17. **JSON 끔(L2) = app-config 키를 지운다** — 빈 문자열은 형식 이름이 아니라 쓰지 않는다 (확인 안 함). 게이트웨이 env 는 `optional: true` 라 키가 없어도 뜬다. 되돌리기는 `apply_overlay local` + 재시작 (P9b `restore_tracing` 과 같은 모양).
18. **L1 측정 방법** — 표지 줄을 api 컨테이너 PID 1(java)의 표준 출력에 직접 쓴다 (`kubectl exec … > /proc/1/fd/1`, 같은 사용자 `app`). **클러스터에서 시험하지 않은 추정** — 안 되면 `.l1.txt` 에 `exec_failed` 가 남고 Task 8 Step 4 시운전에서 드러난다. 해상도 약 1초 (kubectl exec 왕복 · 0.5초 간격).
19. **L3 는 tail 로 미리 뜬다** — 강제 삭제 뒤 kubelet 이 로그 파일을 지우므로 부하 시작 때 노드 컨테이너에서 `timeout … tail -n +1 -f 0.log` 로 떠 둔다 (열린 fd 는 지워져도 끝까지 읽힌다). L4 · L5 는 살아 있는 Pod 라 `kubectl logs` 로 센다. 줄 수는 CRI `F` 줄(잘린 줄 P 는 이어진 한 줄) = Loki 줄.
20. **잃음 · 중복 셈의 창** — Loki 즉시 질의의 범위 (시각 − 범위, 시각] 와 kubectl 줄 시각(초 단위 문자열 비교)을 맞추고, 끝 30초는 수집 중일 수 있어 뺀다. Loki 쪽은 기대 줄 수에 닿을 때까지 5초 간격 60초 기다린다 (Alloy 재시도 백오프).
21. **L6 ③ 억제 확인 = 시험 알림** — `BankDisconnected` 가 울리는 동안 Alertmanager 에 `ErrorLogSurge`(60초 뒤 끝남, 은행 복구 전)를 넣고 `suppressed` · `inhibitedBy` 를 본다, alert-sink 에 오지 않아야 한다. 7 때문에 실제 ErrorLogSurge 는 울리지 않을 것이므로 (그 근거 `err5m_max_with_dlt` 도 같이 기록).
22. **Grafana 12.0.0 설정 이름** — Loki 파생 필드 `matcherType: label` · `matcherRegex: trace_id`(구조화 메타데이터), Tempo `tracesToLogsV2.customQuery: true` · `query`. 프로비저닝 파일의 `$` 는 `$$` (환경변수 치환을 피한다). 스모크는 익명으로 `/api/datasources/uid/loki/health` 를 본다 (Prometheus 로 익명 접근 확인).
23. **check-dashboards 를 Python 으로 나눈다** — P9a 는 모든 `"expr"` 을 promtool 로 검사했다 → Loki 표적은 PromQL 이 아니라 실패한다. 표적의 데이터 소스 종류로 PromQL · LogQL 을 나누고, LogQL 은 check.sh [5/6] 의 Loki 가 검사한다. refId 수 비교는 "표적마다 식이 있다" 단언으로 바뀐다.
24. **CI 이미지 받기 (R6)** — Alloy 는 압축 213MiB 를 노드 3대가 각자 받는다. 먼저 그대로 재고, `k8s-smoke` 가 17분을 넘으면 러너에서 한 번 받아 `kind load` 하는 단계를 더한다 (Task 7 Step 5 — 코드 포함).
