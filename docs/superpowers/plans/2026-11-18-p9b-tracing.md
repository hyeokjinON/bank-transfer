# P9b 분산 추적 — OpenTelemetry (Micrometer Tracing) · Grafana Tempo 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 출금 한 건이 접수(HTTP) → 아웃박스 → Kafka(재시도 · DLT 포함) → 컨슈머 → 게이트웨이(HTTP) → 은행 호출까지 **trace 하나**로 이어지고, 1원인증 동기 경로 · 정리 작업(재발행 · 결과조회)도 추적되게 api · 게이트웨이에 Micrometer Tracing + OpenTelemetry 를 넣고, kind 의 `monitoring` namespace 에 Tempo 를 올려 Grafana 에서 본 뒤, 실험 T1 ~ T5 로 추적 비용 · trace 모양 · 장애 중 trace 를 잰다.

**Architecture:** 대부분은 자동 계측이 잇는다 — MVC · WebFlux 서버, `KafkaTemplate` · 리스너(속성 두 개로 켬), WebClient(관측 레지스트리를 넘김). 자동으로 안 이어지는 곳만 손으로 잇는다: ① 아웃박스 — 행을 쓸 때 지금 구간의 W3C traceparent 를 `outbox_event.trace_parent`(V7)에 저장하고 발행기가 행마다 그것을 부모로 `outbox.publish` 구간을 연다, ② 정리 작업 — 실행 1회 = 새 root `transfer.reconcile`, 건별 구간은 도메인 포트 `ReconcileItemScope` 로, ③ 게이트웨이 은행 호출 — `BankConnectionOwner.withClient` 한 점에서 `bank.request` 구간(Tracer 직접, future 완료 때 닫음), ④ 비교 판 · 실행기 넘김 — JDK HttpClient 는 보내는 쪽 관측을 직접, 1원인증의 `thenApplyAsync` 는 요청 스레드 문맥(ContextSnapshot)을 옮긴다. 내보내기 앞에는 공용 모듈 `modules/tracing` 의 지우개(예외 메시지 · 스택 · 상태 설명 제거)와 actuator 거름을 둔다. Tempo 는 Collector 없이 앱 → OTLP HTTP 직접.

**Tech Stack:** Kotlin 2.3 · Spring Boot 4.1.1 (`spring-boot-starter-opentelemetry`) · Micrometer Tracing 1.7.1 (OTel 브리지) · OpenTelemetry Java 1.62.0 · Spring Kafka 4.1.1 · Spring Framework 7.0.9 · Grafana Tempo 2.10.10 · Grafana 12.0.0 · Prometheus v3.5.0 · kind · kustomize · Bash · k6 · Python 3 (실험 분석만)

**Spec:** `docs/superpowers/specs/2026-11-18-p9b-tracing-design.md` (구속력 있음 — 이 계획이 스펙과 다르게 정한 것은 맨 끝 "계획에서 정한 것", 스펙 §14 에도 같은 목록)

## Global Constraints

스펙 결정 (§2):
- E1: 범위 = 출금 전 구간 + 1원인증 + 로그 traceId. 로그 모으기(P9c) 코드 · 설정을 넣지 않는다.
- E2: 백엔드 = Grafana Tempo (Jaeger 아님). 이미 있는 Grafana 에 데이터 소스로 붙인다.
- E3: **kind 에만** 보낸다 (Compose · IntelliJ 는 보내지 않음). `infra/docker-compose.yml` · `infra/app-smoke.sh` 는 바꾸지 않는다. `apps/api-reactive` · `apps/mock-bank` 는 대상 아님 (api-reactive 는 모듈 기본값으로 컴파일만 유지).
- E4: 계측 = Micrometer Tracing + OpenTelemetry 브리지 (`spring-boot-starter-opentelemetry`), Java 에이전트 없음.
- E5: Collector 없이 앱 → Tempo OTLP **HTTP** 직접 (`http://tempo.monitoring.svc.cluster.local:4318/v1/traces`).
- E6: 아웃박스 행에 W3C `trace_parent`(`VARCHAR(55)`) 를 저장하고 발행기가 행마다 부모로 되살린다.
- E7: 정리 작업 실행 1회 = 새 trace. 처음 trace 와는 `transfer.id` 속성으로 묶는다. 이체 표는 바꾸지 않는다.
- E8: 은행 전문에는 추적을 싣지 않는다. 게이트웨이의 `withClient` 에서 `bank.request` 구간을 연다. 모의 은행은 계측하지 않는다.
- E9: 구간 속성 · 사건 · 상태 설명에 **금액 · 계좌번호 · 예금주 이름 · 1원인증 코드 · Idempotency-Key · 사용자 id 를 넣지 않는다**. 넣는 것: id · 전문번호 · 결과 · 사유 · 종류 · 거래번호(reference).
- E10: 추적 실패는 돈 흐름을 바꾸지 않는다 — 보내기는 비동기 묶음(대기열 2048, 넘치면 버림), 틀린 `trace_parent` 는 새 trace, 예외 없음.

이름 · 값 규칙:
- 서비스 이름 = `spring.application.name` 그대로: api = `bank-transfer`, 게이트웨이 = `bank-gateway`.
- 이 계획의 "구간 이름 · 속성 표"(파일 구조 아래)를 바꾸지 않는다 — 테스트 · 스모크 [11] · 실험 도구가 같은 이름을 grep 한다.
- 우리가 붙이는 속성 값은 문자열 — 단 `reconcile.*` 건수만 숫자(long)다 (의도된 예외: TraceQL 이 `span.reconcile.republished > 0` 으로 비교하게). 결과 · 사유 값은 P9a 지표와 같은 소문자 snake (`ok` `rejected` `not_sent` `unknown`, `not_leader` …).
- 샘플링은 앱 기본 `1.0` (Boot 기본 0.1 을 덮는다). T1 "끔" = `0.0`.
- 지표(P9a)는 바꾸지 않는다: 추적용 구간이 같은 이름의 Timer 를 만들지 않게 `bank.request` 는 Observation 이 아니라 Tracer 로 연다. 새로 생기는 지표는 Spring 이 관측에서 만드는 것뿐 (`http.client.requests` · `spring.kafka.template` · `spring.kafka.listener`, JDK 판 `banktransfer.gateway.http.client`) — 대시보드 · 규칙은 쓰지 않는다.

실행 · 저장소 규칙:
- 커밋 메시지 끝 줄은 정확히 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- 파일을 **이름으로** stage 한다 (`git add -A` · `git add .` 금지). `.run/2. API (8080).run.xml` 은 일부러 수정된 상태(` M`) — **절대 stage 하지 않는다.** `git stash` 금지. `infra/.env` · `postman/` 아래 Postman 이 다시 쓴 파일은 커밋하지 않는다.
- 이미지 버전은 `infra/k8s/versions.env` 한 곳: `TEMPO_VERSION=2.10.10` (2026-10-21 공개 — 2주 이상 지난 2.x 안정판, `docker manifest inspect` 로 amd64 · arm64 확인함). 매니페스트는 태그 없는 이름, `apply_overlay` 가 덮는다. **새 이미지를 처음 받기(up.sh) 전에 사용자 허락을 받는다** (스펙 §6).
- 관측 UI 는 `kubectl port-forward` 로만. kind 포트 매핑을 늘리지 않는다. Tempo · Prometheus 질의는 `kubectl exec deploy/prometheus -- wget` (PC 포트를 열지 않음, `jq` 없이 grep · awk).
- Tempo 는 제어 노드 고정: `nodeSelector: {bank-transfer/role: infra}` + control-plane toleration (P9a 와 같은 자리).
- 스크립트는 Git Bash · Linux 둘 다에서 돈다. 실험 분석의 JSON 파싱만 Python 3 (`python3` → `python` 순서로 찾는다, PC 전용 — CI 는 쓰지 않음).
- `.gitignore` 가 `*.log` 를 무시한다 → 원자료 로그는 `.txt`.
- 새 yaml · sh · awk · py 는 LF (`.gitattributes` 에 `*.py text eol=lf` 를 Task 12 에서 더한다).
- 주석 · 테스트 이름 · 문서는 한국어 (기존 스타일). 테스트는 kotlin.test + 백틱 한국어 이름. 테스트 JVM 은 `-Duser.timezone=UTC`.
- `spring-boot-micrometer-tracing-test` · `spring-boot-starter-opentelemetry-test` 를 의존성에 넣지 않는다 (아래 "확인한 사실" — 테스트의 전파를 끈다).
- 전 직장 코드 · 민감정보(IP · 계정 · 키)를 저장소에 넣지 않는다.

```kotlin
package io.github.hyeokjinon.banktransfer.tracing

import io.opentelemetry.api.common.AttributeKey
import io.opentelemetry.api.common.Attributes
import io.opentelemetry.sdk.common.CompletableResultCode
import io.opentelemetry.sdk.trace.data.DelegatingSpanData
import io.opentelemetry.sdk.trace.data.EventData
import io.opentelemetry.sdk.trace.data.SpanData
import io.opentelemetry.sdk.trace.data.StatusData
import io.opentelemetry.sdk.trace.export.SpanExporter

/**
 * 내보내기 앞 지우개 (P9b 결정 E9). 구간에 예외가 남을 때 브리지는 메시지 · 스택(`exception` 사건)과 상태 설명(= 메시지)을 같이 남긴다.
 * 도메인 예외 메시지에는 사용자 id · 금액이(예 `StoreConflict.InsufficientBalance`), 입력 검증 메시지에는 거절된 값(계좌번호 등)이 들어갈 수 있다 —
 * 보내기 전에 `exception.type` 만 남기고 상태 설명은 비운다. 속성 이름 · 값 자체는 코드가 붙이는 것이라 건드리지 않는다 (붙이는 쪽 규칙: 구간 표).
 * 상태 코드(ERROR)는 그대로 — "실패한 구간" 은 보인다.
 */
class ScrubbingSpanExporter(private val delegate: SpanExporter) : SpanExporter {

    override fun export(spans: Collection<SpanData>): CompletableResultCode = delegate.export(spans.map(::scrub))

    override fun flush(): CompletableResultCode = delegate.flush()

    override fun shutdown(): CompletableResultCode = delegate.shutdown()

    private class Scrubbed(span: SpanData) : DelegatingSpanData(span) {
        private val events: List<EventData> = span.events.map { e ->
            if (e.name != EXCEPTION_EVENT) e
            else EventData.create(e.epochNanos, e.name, Attributes.of(EXCEPTION_TYPE, e.attributes.get(EXCEPTION_TYPE) ?: "unknown"))
        }
        private val status: StatusData = StatusData.create(span.status.statusCode, "")

        override fun getEvents(): List<EventData> = events

        override fun getStatus(): StatusData = status
    }

    companion object {
        private const val EXCEPTION_EVENT = "exception"
        private val EXCEPTION_TYPE: AttributeKey<String> = AttributeKey.stringKey("exception.type")

        /** 지울 것이 없으면 그대로 돌려준다 (대부분의 구간 — 복사 비용을 치르지 않는다). */
        fun scrub(span: SpanData): SpanData =
            if (span.status.description.isEmpty() && span.events.none { it.name == EXCEPTION_EVENT }) span else Scrubbed(span)

        /** Boot 가 만든 내보내기(OTLP 등)를 모두 감싼다. 이미 감싼 것은 다시 감싸지 않는다. */
        fun wrapAll(exporters: List<SpanExporter>): List<SpanExporter> =
            exporters.map { if (it is ScrubbingSpanExporter) it else ScrubbingSpanExporter(it) }
    }
}

package io.github.hyeokjinon.banktransfer.tracing

import io.micrometer.tracing.Span
import io.micrometer.tracing.exporter.FinishedSpan
import io.micrometer.tracing.exporter.SpanExportingPredicate

/**
 * actuator 요청 구간은 내보내지 않는다 (P9b). kubelet 프로브(Pod 마다 수 초) · Prometheus 수집(5초 × Pod 4)이 업무 trace 를 덮지 않게.
 * 지표가 아니라 내보내기만 거른다 — P9a 의 http_server_requests 는 그대로다. Boot 의 묶음 처리기(BatchSpanProcessor)가 이 빈을 쓴다.
 */
class ActuatorSpans : SpanExportingPredicate {
    override fun isExportable(span: FinishedSpan): Boolean {
        if (span.kind != Span.Kind.SERVER) return true
        val uri = span.tags["uri"].orEmpty()
        val url = span.tags["http.url"].orEmpty()
        return !(uri.startsWith(ACTUATOR) || url.contains(ACTUATOR))
    }

    private companion object {
        const val ACTUATOR = "/actuator"
    }
}

import io.github.hyeokjinon.banktransfer.tracing.ScrubbingSpanExporter
import io.opentelemetry.api.common.AttributeKey
import io.opentelemetry.sdk.testing.exporter.InMemorySpanExporter
import io.opentelemetry.sdk.trace.SpanProcessor
import io.opentelemetry.sdk.trace.data.SpanData

import org.springframework.boot.test.context.TestConfiguration

/**
 * 공유 컨텍스트가 끝낸 구간을 메모리에 모은다 (P9b). 공유 컨텍스트라 다른 테스트의 구간도 섞인다 — 추적 테스트는 [clear] 로 시작하고 속성 · traceId 로 거른다.
 * InMemorySpanExporter 를 SpanExporter 빈으로 올리지 않는다 — 올리면 Boot 의 5초 묶음 처리기에도 들어가 같은 구간이 두 번 온다.
 */
class TestSpans {
    val exporter: InMemorySpanExporter = InMemorySpanExporter.create()

    fun all(): List<SpanData> = exporter.finishedSpanItems

    fun ofTrace(traceId: String): List<SpanData> = all().filter { it.traceId == traceId }

    fun clear() = exporter.reset()
}

fun SpanData.attr(key: String): String? = attributes.get(AttributeKey.stringKey(key))

fun SpanData.service(): String? = resource.getAttribute(AttributeKey.stringKey("service.name"))

@TestConfiguration(proxyBeanMethods = false)
class TracingTestConfiguration {
    @Bean
    fun testSpans() = TestSpans()

    /** 끝나는 즉시 같은 스레드에서 넘긴다 (5초 묶음 없이). 운영과 같은 지우개를 지난다 — 금지 속성 테스트(E9)가 지운 뒤 모양을 본다. */
    @Bean
    fun testSpanProcessor(spans: TestSpans): SpanProcessor = SimpleSpanProcessor.create(ScrubbingSpanExporter(spans.exporter))
}

/** P9b 자동 구간 (스펙 §3 · §5): MVC 서버 · KafkaTemplate · 리스너는 설정만으로 구간이 되고 traceparent 헤더로 이어진다. @Scheduled 는 구간을 만들지 않는다. */
class AutoSpansTest : ApiIntegrationTest() {
    @Autowired private lateinit var spans: TestSpans
    @Autowired private lateinit var kafka: KafkaTemplate<String, String>
    @Autowired private lateinit var tracer: Tracer
    @Autowired private lateinit var observations: ObservationRegistry

    @Test
    fun `HTTP 요청은 SERVER 구간 - 서비스 이름은 spring application name`() {
        spans.clear()
        val user = fundedUser(1_000)
        client.get().uri("/api/v1/wallet").header(USER_ID_HEADER, user).retrieve().toBodilessEntity()

        await.atMost(Duration.ofSeconds(5)) untilAsserted {
            val server = spans.all().single { it.kind == SpanKind.SERVER && it.attr("uri") == "/api/v1/wallet" }
            assertEquals("http get /api/v1/wallet", server.name)
            assertEquals("bank-transfer", server.service())
        }
    }

    @Test
    fun `KafkaTemplate 발행 · 리스너 소비가 구간이 되고 traceparent 헤더로 이어진다`() {
        spans.clear()
        val parent = tracer.nextSpan().name("test-parent").start()
        val key = UUID.randomUUID().toString()   // 없는 이체 id — 컨슈머는 NOT_FOUND 로 끝낸다 (돈 영향 없음)
        tracer.withSpan(parent).use { kafka.send(TransferTopics.REQUESTED, key, """{"transferId":"$key"}""").get(5, TimeUnit.SECONDS) }
        parent.end()

        await.atMost(Duration.ofSeconds(10)) untilAsserted {
            val trace = spans.ofTrace(parent.context().traceId())
            val send = trace.single { it.kind == SpanKind.PRODUCER }
            val process = trace.single { it.kind == SpanKind.CONSUMER }
            assertEquals("transfer.requested send", send.name)
            assertEquals("transfer.requested process", process.name)
            assertEquals(parent.context().spanId(), send.parentSpanId)
            assertEquals(send.spanId, process.parentSpanId)
        }
    }

    @Test
    fun `@Scheduled 실행 관측은 꺼져 있다 - 발행기 0점5초마다 빈 trace 가 쌓이지 않게`() {
        assertTrue(Observation.createNotStarted("tasks.scheduled.execution", observations).isNoop)
        assertFalse(Observation.createNotStarted("http.server.requests", observations).isNoop)
    }
}

/**
 * api 추적 조립 (P9b). 구간 · 전파 · 로그 상관은 Boot 자동 구성(Micrometer Tracing + OTel 브리지)이 하고, 여기는 내보내기 앞단과 손으로 잇는 곳의 도구만 둔다.
 * - spanExporters: Boot 의 같은 이름 빈(@ConditionalOnMissingBean)을 대신해 모든 내보내기를 지우개로 감싼다 (E9).

package io.github.hyeokjinon.banktransfer.api.tracing

import io.micrometer.tracing.Tracer
import io.micrometer.tracing.propagation.Propagator

/**
 * 아웃박스를 건너는 추적 문맥 (P9b 스펙 §4-1, 결정 E6 · E10). "DB 에 쓰고 0.5초 뒤 다른 스레드가 꺼낸다" 는 틈을 프레임워크는 모른다.
 * - 쓰기: 접수(saveWithEvent) · 재발행(republish)이 행을 만들 때 [currentTraceParent] 를 outbox_event.trace_parent 에 넣는다.
 * - 읽기: 발행기가 행마다 [publishing] — 저장값을 부모로 `outbox.publish` 구간을 열고 그 범위 안에서 kafka.send → Kafka producer 구간 + traceparent 헤더.
 *   행마다 열고 닫는다 — 문맥이 다음 행으로 새지 않는다 (위험 C1).
 * - 저장값이 NULL · 형식이 틀리면 부모 없이 새 trace (예외 없음, E10). 전파가 꺼져 있으면(Propagator.NOOP) 쓰는 값도 null.
 * - 속성: transfer.id · outbox.event_id 만 (E9).
 */
class OutboxTracing(private val tracer: Tracer, private val propagator: Propagator) {

    /** 지금 구간의 W3C traceparent. 구간이 없거나 전파가 꺼져 있으면 null. 샘플링 0 이면 끝 깃발이 00 (전파는 계속된다). */
    fun currentTraceParent(): String? {
        val context = tracer.currentTraceContext().context() ?: return null
        val carrier = HashMap<String, String>()
        propagator.inject(context, carrier) { c, key, value -> c?.put(key, value) }
        return carrier[TRACEPARENT]?.takeIf(::isValid)
    }

    /** [traceParent] 를 부모로 `outbox.publish` 를 열고 그 범위 안에서 [send]. [send] 의 예외는 구간에 남기고 그대로 던진다. */
    fun <T> publishing(traceParent: String?, transferId: String, eventId: Long, send: () -> T): T {
        val builder = if (isValid(traceParent)) propagator.extract(traceParent!!, GETTER) else tracer.spanBuilder().setNoParent()
        val span = builder.name(SPAN_NAME)
            .tag(TraceKeys.TRANSFER_ID, transferId)
            .tag(TraceKeys.OUTBOX_EVENT_ID, eventId.toString())
            .start()
        try {
            return tracer.withSpan(span).use { send() }
        } catch (e: Throwable) {
            span.error(e)
            throw e
        } finally {
            span.end()
        }
    }

    companion object {
        const val TRACEPARENT = "traceparent"
        const val SPAN_NAME = "outbox.publish"

        /** W3C trace-context 버전 00: 소문자 hex, trace id · span id 가 모두 0 이면 무효. */
        private val W3C = Regex("^00-(?!0{32})[0-9a-f]{32}-(?!0{16})[0-9a-f]{16}-[0-9a-f]{2}$")

        /** 운반체 = 저장된 traceparent 문자열 하나. 다른 이름(tracestate · b3 …)은 없다. */
        private val GETTER = Propagator.Getter<String> { carrier, key -> if (key == TRACEPARENT) carrier else null }

        fun isValid(traceParent: String?): Boolean = traceParent != null && W3C.matches(traceParent)

        val NOOP = OutboxTracing(Tracer.NOOP, Propagator.NOOP)
    }
}

) {

    /** 최대 batchSize 건을 발행하고, 발행한 건수를 돌려준다. */
    fun publishPending(): Int =
        tx.execute {
            val events = jdbc.query(
                SELECT_PENDING_SQL,
                { rs, _ -> PendingEvent(rs.getLong("id"), rs.getString("aggregate_id"), rs.getString("message"), rs.getString("trace_parent")) },
                batchSize,
            )
            // 전부 보내 놓고 나서 기다린다: 대기가 건마다 쌓이지 않고 묶음 전체에 5초 안팎으로 끝난다. 구간은 행마다 열고 닫는다 (P9b)
            val futures = events.map { e ->
                tracing.publishing(e.traceParent, e.aggregateId, e.id) { kafka.send(TransferTopics.REQUESTED, e.aggregateId, e.message) }
            }
            futures.forEach { it.get(SEND_TIMEOUT_SECONDS, TimeUnit.SECONDS) }
            jdbc.batchUpdate(
                "UPDATE outbox_event SET published_at = NOW(6) WHERE id = ?",
                events.map { arrayOf<Any>(it.id) },
            )
            events.size
        }!!

    private data class PendingEvent(val id: Long, val aggregateId: String, val message: String, val traceParent: String?)
```

 * 결과조회 · 재발행 한 건 = 자식 구간(transfer.id · transfer.reference). 재발행이 쓰는 아웃박스 행의 trace_parent 는 그 건 구간이라
 * 재발행 뒤 Kafka → 게이트웨이 구간이 이 실행 trace 에 이어진다. @Scheduled 관측은 꺼 두었다 (application.yml) — root 는 여기서만 연다.
 */
class ReconcileTracing(private val tracer: Tracer) : ReconcileItemScope {

    fun reconcile(run: () -> ReconcileResult): ReconcileResult {
        val span = tracer.spanBuilder().setNoParent().name(ROOT).start()
        try {
            val result = tracer.withSpan(span).use { run() }
            span.tag("reconcile.republished", result.republished.toLong())
                .tag("reconcile.abandoned", result.abandoned.toLong())
                .tag("reconcile.marked_unknown", result.markedUnknown.toLong())
                .tag("reconcile.completed", result.completed.toLong())
                .tag("reconcile.failed", result.failed.toLong())
                .tag("reconcile.still_unknown", result.stillUnknown.toLong())
                .tag("reconcile.gave_up", result.gaveUp.toLong())
                .tag("reconcile.errors", result.errors.toLong())
            return result
        } catch (e: Throwable) {
            span.error(e)
            throw e
        } finally {
            span.end()
        }
    }

    override fun <T> inquiry(transfer: Transfer, block: () -> T): T = item(INQUIRY, transfer, block)

    override fun <T> republish(transfer: Transfer, block: () -> T): T = item(REPUBLISH, transfer, block)

    private fun <T> item(name: String, transfer: Transfer, block: () -> T): T {
        val span: Span = tracer.nextSpan().name(name)
            .tag(TraceKeys.TRANSFER_ID, transfer.id.toString())
            .tag(TraceKeys.TRANSFER_REFERENCE, transfer.reference)
            .start()
        try {
            return tracer.withSpan(span).use { block() }
        } catch (e: Throwable) {
            span.error(e)
            throw e
        } finally {
            span.end()
        }
    }

    companion object {
        const val ROOT = "transfer.reconcile"
        const val INQUIRY = "transfer.inquiry"
        const val REPUBLISH = "transfer.republish"
        val NOOP = ReconcileTracing(Tracer.NOOP)
    }
}

import io.github.hyeokjinon.banktransfer.protocol.InquiryResponse
import io.github.hyeokjinon.banktransfer.protocol.NameInquiryResponse
import io.github.hyeokjinon.banktransfer.protocol.TransferResponse

import java.net.URI
import java.net.http.HttpClient
import java.net.http.HttpRequest
import java.net.http.HttpResponse

/**
 * JDK java.net.http.HttpClient 판 — 비교용 (P8-1, 스펙 §5-2).
 * sendAsync 가 CompletableFuture 를 그대로 돌려준다. 응답은 셀렉터 스레드가 읽고, future 완료 · 뒤처리는 기본 실행기
 * (늘어나는 캐시 스레드 풀 — 이것 자체가 비교 대상이라 바꾸지 않는다)에서 돈다.
 * 연결 풀 개수 상한이 없고 조절할 수 없다. POST 는 연결이 끊겨도 다시 보내지 않는다 (jdk.httpclient.enableAllMethodRetry 기본 false).
 * HTTP/2 를 먼저 시도하는 기본값 대신 HTTP/1.1 로 고정한다 — WebClient 판과 같은 조건으로 비교한다.
 * P9b: JDK HttpClient 는 자동 계측이 없다 — 보내는 쪽 관측([OBSERVATION])을 직접 연다. 시작할 때 추적 처리기가 setter 로 traceparent 를 요청 builder 에 넣으므로
 * build 는 시작 뒤에 한다. 닫는 쪽은 완료 콜백(HttpClient 스레드) — 관측 객체를 직접 들고 닫는다.
 */
class JdkHttpBankGateway(
    private val settings: HttpGatewaySettings,
    private val observations: ObservationRegistry = ObservationRegistry.NOOP,
) : HttpBankGateway {

    private val http: HttpClient = HttpClient.newBuilder()
        .version(HttpClient.Version.HTTP_1_1)
        .connectTimeout(settings.connectTimeout)
        .build()

    override fun inquireName(bankCode: String, accountNo: String): CompletableFuture<NameInquiryResponse> =
        post(GatewayPaths.NAME_INQUIRIES, NameInquiryBody(bankCode, accountNo)) { GatewayJson.read(it, NameInquiryResult::class.java).toResponse() }

    override fun transfer(bankCode: String, accountNo: String, amount: Long, memo: String, reference: String): CompletableFuture<TransferResponse> =
        post(GatewayPaths.TRANSFERS, TransferBody(bankCode, accountNo, amount, memo, reference)) { GatewayJson.read(it, TransferResult::class.java).toResponse() }

    override fun inquire(reference: String): CompletableFuture<InquiryResponse> =
        post(GatewayPaths.INQUIRIES, InquiryBody(reference)) { GatewayJson.read(it, InquiryResult::class.java).toResponse() }

    private fun <T> post(path: String, body: Any, parse: (String) -> T): CompletableFuture<T> {
        val builder = HttpRequest.newBuilder(URI.create(settings.baseUrl + path))
            .timeout(settings.responseTimeout)
            .header("Content-Type", "application/json")
            .POST(HttpRequest.BodyPublishers.ofString(GatewayJson.write(body)))
        val context = RequestReplySenderContext<HttpRequest.Builder, HttpResponse<String>> { carrier, key, value -> carrier?.setHeader(key, value) }
        context.carrier = builder
        context.remoteServiceName = REMOTE_SERVICE
        val observation = Observation.createNotStarted(OBSERVATION, { context }, observations)
            .contextualName("http post")
            .lowCardinalityKeyValue("uri", path)
            .lowCardinalityKeyValue("client", "jdk")
            .start()
        val sent = try {
            http.sendAsync(builder.build(), HttpResponse.BodyHandlers.ofString())
        } catch (e: RuntimeException) {
            observation.error(e)
            observation.stop()
            throw e
        }
        return sent
            .whenComplete { response, error ->
                if (error != null) observation.error(error) else context.response = response
                observation.stop()
            }
            .handle { response, error ->
                if (error != null) throw HttpFailures.fromTransport(error)
                HttpFailures.parse(response.statusCode(), response.body(), parse)
            }
    }

    override fun close() {
        http.close()   // Java 21: HttpClient 는 AutoCloseable
    }

    companion object {
        /** JDK 판 클라이언트 관측 이름 (P9b). 관측이 지표도 만든다 — 이름 규칙(banktransfer.)을 따르고, WebClient 의 http.client.requests 와 태그 모양을 섞지 않는다. */
        const val OBSERVATION = "banktransfer.gateway.http.client"
        private const val REMOTE_SERVICE = "bank-gateway"
    }
}

 * 지금 스레드의 ThreadLocal 문맥(관측 · 추적 — context-propagation 에 등록된 것 모두)을 [executor] 의 작업으로 옮긴다 (P9b).

import io.github.hyeokjinon.banktransfer.gateway.BankNotSentException
import io.github.hyeokjinon.banktransfer.gatewayapp.metrics.BankRequestType

/**
 * 은행 호출 구간 `bank.request` (P9b 스펙 §4-3, 결정 E8 · E9). 전문 규격에 추적 자리가 없어 모의 은행으로 넘기지 않는다 —
 * 게이트웨이의 은행 호출 한 점(BankConnectionOwner.withClient)에서 열고 future 가 끝날 때 닫는다.
 * - 부모 = 지금 구간(서버 요청). 닫는 쪽은 은행 Netty 이벤트 루프의 완료 콜백 — 구간 객체를 직접 들고 닫는다 (스레드 지역 문맥에 기대지 않음, 위험 C4).
 * - Observation 이 아니라 Tracer 로 연다: 관측이면 P9a 의 Timer(banktransfer.gateway.bank.request)와 같은 이름의 지표가 다른 태그로 하나 더 생긴다.
 * - 결과 분류는 지표와 같은 [GatewayMetrics.outcomeOf]. 속성에 계좌 · 금액 · 예금주를 넣지 않는다 — 거래번호(reference)는 결과조회 키라 넣는다.
 */
class BankRequestTracing(private val tracer: Tracer) {

    fun start(type: BankRequestType, reference: String?): Span {
        val span = tracer.nextSpan().name(SPAN_NAME).tag(TYPE, type.tag)
        if (reference != null) span.tag(REFERENCE, reference)
        return span.start()
    }

    fun end(span: Span, value: Any?, error: Throwable?) {
        span.tag(OUTCOME, GatewayMetrics.outcomeOf(value, error).tag)
        (value as? BankMessage)?.let { span.tag(TRAN_NO, it.header.tranNo.toString()) }
        when (val cause = unwrap(error)) {
            null -> {}
            is BankNotSentException -> span.tag(NOT_SENT_REASON, cause.reason.tag)
            else -> span.tag(ERROR_TYPE, cause.javaClass.simpleName)   // 메시지는 남기지 않는다 (E9)
        }
        span.end()
    }

    private fun unwrap(e: Throwable?): Throwable? = if (e is CompletionException && e.cause != null) e.cause else e

    companion object {
        const val SPAN_NAME = "bank.request"
        const val TYPE = "bank.request.type"
        const val OUTCOME = "bank.outcome"
        const val TRAN_NO = "bank.tran_no"
        const val NOT_SENT_REASON = "bank.not_sent.reason"
        const val REFERENCE = "transfer.reference"
        const val ERROR_TYPE = "error.type"
        val NOOP = BankRequestTracing(Tracer.NOOP)
    }
}

    private fun <T> withClient(type: BankRequestType, reference: String?, call: (BankGatewayClient) -> CompletableFuture<T>): CompletableFuture<T> {
        val startedAt = System.nanoTime()
        val span = tracing.start(type, reference)
        val result = dispatch(call)
        result.whenComplete { value, error ->
            metrics.recordBankCall(type, System.nanoTime() - startedAt, value, error)
            tracing.end(span, value, error)
        }
        return result
    }

package io.github.hyeokjinon.banktransfer.api.support

import com.google.protobuf.ByteString
import com.sun.net.httpserver.HttpServer
import io.opentelemetry.proto.collector.trace.v1.ExportTraceServiceRequest
import java.net.InetSocketAddress
import java.util.concurrent.CopyOnWriteArrayList

/**
 * 별도 JVM 게이트웨이가 OTLP HTTP 로 보내는 구간을 받는다 (P9b — 진짜 Tempo 대신). 본문 = protobuf ExportTraceServiceRequest.
 * 게이트웨이에 `--management.opentelemetry.tracing.export.otlp.endpoint=<endpoint>` 를 주면 운영과 같은 보내기 경로(지우개 포함)를 지난다.
 */
class OtlpReceiver : AutoCloseable {
    data class ReceivedSpan(
        val service: String,
        val traceId: String,
        val spanId: String,
        val parentSpanId: String,
        val name: String,
        val attributes: Map<String, String>,
    )

    private val received = CopyOnWriteArrayList<ReceivedSpan>()

    private val server: HttpServer = HttpServer.create(InetSocketAddress("127.0.0.1", 0), 0).apply {
        createContext("/v1/traces") { ex ->
            val request = ex.requestBody.use { ExportTraceServiceRequest.parseFrom(it) }
            request.resourceSpansList.forEach { rs ->
                val service = rs.resource.attributesList.firstOrNull { it.key == "service.name" }?.value?.stringValue.orEmpty()
                rs.scopeSpansList.flatMap { it.spansList }.forEach { s ->
                    received += ReceivedSpan(
                        service, s.traceId.hex(), s.spanId.hex(), s.parentSpanId.hex(), s.name,
                        s.attributesList.associate { it.key to it.value.stringValue },
                    )
                }
            }
            ex.responseHeaders.add("Content-Type", "application/x-protobuf")
            ex.sendResponseHeaders(200, -1)   // 빈 ExportTraceServiceResponse = 전부 받음
            ex.close()
        }
        start()
    }

    val endpoint: String get() = "http://127.0.0.1:${server.address.port}/v1/traces"

    fun spans(): List<ReceivedSpan> = received.toList()

    override fun close() = server.stop(0)

    private fun ByteString.hex(): String = toByteArray().joinToString("") { "%02x".format(it) }
}

```python
#!/usr/bin/env python3
"""P9b T2 — 출금 trace 모양 (load/k8s/p9b.sh 가 부른다, PC 전용).

입력: <동작>-<회차>.traces.txt — 한 줄 = "<출금 id>\t<Tempo /api/traces/<traceID> JSON>" (못 찾은 건은 {}).
출력: JSON 한 줄.
  traces          trace 를 찾은 출금 수
  complete        서비스 bank-transfer · bank-gateway 둘 다 + 구간 5개 이상인 trace 수 (성공 기준 2)
  spans_min/max   trace 하나의 구간 수
  accept_to_publish_ms  접수 server 끝 → outbox.publish 시작 (발행 주기 0.5초 근처여야 — 아웃박스 틈)
  consumer_to_bank_ms   첫 소비 시작 → bank.request 시작 (컨슈머 · HTTP · 게이트웨이 경로)
  bank_ms               bank.request 길이 (게이트웨이 → 은행 → 응답)
  e2e_ms                접수 server 시작 → bank.request 끝
  각각 _p50 · _p95 (가장 가까운 순위)
"""
import json
import math
import sys


def spans_of(doc):
    batches = doc.get("batches") or doc.get("resourceSpans") or (doc.get("trace") or {}).get("resourceSpans") or []
    out = []
    for batch in batches:
        attrs = (batch.get("resource") or {}).get("attributes") or []
        service = next((a.get("value", {}).get("stringValue", "") for a in attrs if a.get("key") == "service.name"), "")
        for scope in batch.get("scopeSpans") or batch.get("instrumentationLibrarySpans") or []:
            for span in scope.get("spans") or []:
                out.append({
                    "service": service,
                    "name": span.get("name", ""),
                    "start": int(span.get("startTimeUnixNano", 0)),
                    "end": int(span.get("endTimeUnixNano", 0)),
                })
    return out


def first(spans, pred):
    found = [s for s in spans if pred(s)]
    return min(found, key=lambda s: s["start"]) if found else None


def pct(values, p):
    if not values:
        return None
    ordered = sorted(values)
    k = max(0, min(len(ordered) - 1, math.ceil(p / 100.0 * len(ordered)) - 1))
    return round(ordered[k], 1)


def main(path):
    traces = complete = 0
    counts, accept_to_publish, consumer_to_bank, bank, e2e = [], [], [], [], []
    with open(path, encoding="utf-8") as f:
        for line in f:
            _, _, raw = line.rstrip("\n").partition("\t")
            try:
                spans = spans_of(json.loads(raw or "{}"))
            except ValueError:
                continue
            if not spans:
                continue
            traces += 1
            counts.append(len(spans))
            if {"bank-transfer", "bank-gateway"} <= {s["service"] for s in spans} and len(spans) >= 5:
                complete += 1
            server = first(spans, lambda s: s["service"] == "bank-transfer" and s["name"].startswith("http post /api/v1/transfers"))
            publish = first(spans, lambda s: s["name"] == "outbox.publish")
            consumer = first(spans, lambda s: s["name"] == "transfer.requested process")
            request = first(spans, lambda s: s["name"] == "bank.request")
            if server and publish:
                accept_to_publish.append((publish["start"] - server["end"]) / 1e6)
            if consumer and request:
                consumer_to_bank.append((request["start"] - consumer["start"]) / 1e6)
            if request:
                bank.append((request["end"] - request["start"]) / 1e6)
            if server and request:
                e2e.append((request["end"] - server["start"]) / 1e6)
    out = {"traces": traces, "complete": complete, "spans_min": min(counts) if counts else None, "spans_max": max(counts) if counts else None}
    for name, values in (("accept_to_publish_ms", accept_to_publish), ("consumer_to_bank_ms", consumer_to_bank), ("bank_ms", bank), ("e2e_ms", e2e)):
        out[name + "_p50"] = pct(values, 50)
        out[name + "_p95"] = pct(values, 95)
    print(json.dumps(out, ensure_ascii=False))


if __name__ == "__main__":
    main(sys.argv[1])
```

## 계획에서 정한 것 (스펙이 비었거나 코드 · 라이브러리와 달랐던 곳)

1. **Kafka 관측 속성 이름 확인** — `spring.kafka.template.observation-enabled` · `spring.kafka.listener.observation-enabled` 가 Boot 4.1.1 에 그대로 있고 기본 `false` (jar 메타데이터). 코드 없이 yml 두 줄. 재시도 · DLT 발행은 자동 구성 템플릿을 쓰고(유일한 `KafkaOperations` 빈), Spring Kafka 4.1.1 은 오류 처리기를 소비 구간 범위 안에서 부른다(바이트코드) → 재시도 체인이 같은 trace 라는 스펙 가정이 맞다. 확인은 Task 3 통합 2.
2. **"보내기 끔" 을 `management.tracing.export.enabled=false` 로 하지 않는다** — Boot 4.1 에서 이 값은 전파기까지 끈다 (스펙 §3 표는 기본 false 로 적었음). 대신 **주소가 없으면 보내지 않는다**: OTLP 내보내기는 `…otlp.endpoint` 가 있을 때만 생긴다. 앱 기본 = 주소 없음(구간 · 전파 · 로그 상관은 어디서나 켜짐), kind 의 app-config 만 주소를 준다. T1 "끔" = 샘플링 0.
3. **테스트 자동 구성 모듈을 넣지 않는다** — `spring-boot-micrometer-tracing-test`(· `…starter-opentelemetry-test`)는 `@AutoConfigureTracing` 없는 모든 테스트에 export.enabled=false 를 넣어 2 때문에 전파가 꺼진다. 메모리 구간은 OTel `opentelemetry-sdk-testing` 의 `InMemorySpanExporter` 를 **`SimpleSpanProcessor` 빈**으로 (SpanExporter 빈이면 5초 묶음에도 들어간다).
4. **OTLP 지표 끔** — 스타터가 `micrometer-registry-otlp` 를 끌어와 1분마다 `localhost:4318/v1/metrics` 로 민다 (스펙에 없음). `management.otlp.metrics.export.enabled=false` (P9a 는 Prometheus 수집).
5. **@Scheduled 관측 끔** — Boot 가 @Scheduled 실행마다 관측해 발행기 0.5초 · 정리 10초마다 root trace 가 생긴다 (스펙 §4-1 "발행기 주기 실행은 관측하지 않는다" 의 실제 방법). `management.observations.enable.[tasks.scheduled.execution]=false` — 이 지표는 대시보드 · 규칙에서 쓰지 않는다 (grep 0). 정리 작업 root 는 코드가 연다 (Task 4).
6. **actuator 구간 거름** (스펙에 없음) — 프로브 · Prometheus 수집(5초 × Pod 4)이 trace 를 덮지 않게 `SpanExportingPredicate` 로 내보내기만 거른다 (지표는 그대로). 스모크 [11] 이 0 을 본다.
7. **내보내기 앞 지우개 + 공용 모듈 `modules/tracing`** (스펙에 없음 — E9 를 지키는 데 필요) — 브리지가 예외를 남길 때 메시지 · 스택 · 상태 설명을 같이 남긴다. 도메인 예외(`StoreConflict.InsufficientBalance` = 사용자 id · 금액) · 검증 메시지(거절된 계좌번호)가 Tempo 로 갈 수 있다 → `ScrubbingSpanExporter` 가 `exception.type` 만 남긴다. Boot 의 `spanExporters`(@ConditionalOnMissingBean)를 대신하는 빈으로 모든 내보내기를 감싼다. 두 앱이 같이 쓰므로 작은 모듈로 (Spring 비의존). Task 6 Step 5 의 WebFlux 대안(ReactiveGatewayController 의 문맥 복원)을 썼다면 여기에 덧붙인다.
8. **아웃박스 복원 = `outbox.publish` 구간** — 스펙은 "저장값을 부모로 하는 범위" 였다. 저장값으로 `Propagator.extract` 해 행마다 짧은 구간을 열고(틀리면 `setNoParent`) 그 안에서 send → Kafka 자동 producer 구간은 사용자 속성을 받지 못하므로 `transfer.id` · `outbox.event_id` 를 이 구간에 둔다, 행마다 열고 닫아 문맥이 새지 않는다 (C1), 접수 → 발행 틈이 trace 에서 보인다. 구간이 행마다 하나 는다 (구간 표).
9. **WebClient 는 관측 레지스트리를 직접 넘긴다** — `modules/bank-gateway-http` 가 `WebClient.builder()` 로 만든다 (Boot Builder 아님). `HttpBankGateway.create(kind, settings, observations)` 로 Boot 의 레지스트리를 넘긴다. WebClient 는 부모를 Reactor 문맥에서만 찾지만(null) 추적 처리기가 `tracer.currentSpan()` 으로 대신 찾는다 → 컨슈머 스레드에서 부르면 이어진다 (바이트코드 · Task 7).
10. **코루틴은 설정 한 줄** — Spring 7.0.9 `CoroutinesUtils.invokeSuspendingFunction` 이 자동 문맥 전파가 켜져 있으면 `PropagationContextElement` 를 붙인다 → `spring.reactor.context-propagation=auto` (스펙 §4-4 "정확한 API 는 계획에서"). 코드 변경 없음, Task 7 이 확인 (끊기면 `withContext(db + PropagationContextElement())`). 비동기 실패 경로의 재시도 발행은 소비 구간 밖이라 새 trace 일 수 있다 — 시험하지 않음 (측정 문서 한계). **→ 설정 한 줄로는 부족했다, 23.**
11. **1원인증 실행기 넘김** (스펙에 없음) — 성명조회 응답 뒤 1원 이체 HTTP 가 `thenApplyAsync` 의 앱 실행기 스레드에서 불려 trace 가 끊긴다. `BankGatewayAdapter` 가 요청 스레드에서 `ContextSnapshot` 을 잡아 실행기를 감싼다 (`carryContext`). 실행기 전체에 TaskDecorator 를 거는 것은 제출 시점(Netty 스레드)에 잡아 틀리다.
12. **`bank.request` 는 Observation 이 아니라 Tracer** — Observation 이면 P9a 의 `banktransfer.gateway.bank.request` Timer 와 같은 이름의 지표가 다른 태그로 생긴다. 속성에 `error.type`(예외 클래스 이름 — 메시지 없음)을 더했다.
13. **정리 작업 건별 구간 = 도메인 포트 `ReconcileItemScope`** — 결과조회 · 재발행 한 건에 transfer.id 를 붙이려면 반복문 안에 자리가 필요하다 (스펙 §1 기준 3). 도메인은 추적을 모르므로 기본 no-op 포트, apps/api 의 `ReconcileTracing` 이 구현. 재발행 행의 trace_parent 는 그 건 구간 → 재발행 뒤 Kafka · 게이트웨이 구간이 정리 작업 trace 에 붙는다.
14. **소비 구간의 `transfer.reference` 는 뺀다** — 컨슈머는 key(이체 id)만 알고 거래번호는 DB 를 읽은 뒤다. 거래번호는 같은 trace 의 `bank.request` 에 있다 (스펙 §5 표의 소비 구간 속성 줄).
15. **T1 처리량의 정의** — k6 는 고정 도착률이라 "초당 접수" 는 켬 · 끔이 같을 수밖에 없다. 처리량 = 출금 수 ÷ (부하 + 마무리 대기) 초 (`completed_per_s`), CPU 는 부하 동안 `process_cpu_usage` 평균의 Pod 합. 포화 근처 비교로 40건/s × 30초 쌍(T1c)을 더했다 (같은 1,200건 — 시드 잔고 그대로). 회차마다 재시작해 조건을 같게.
16. **Tempo 2.10.10** — 3.x 가 있지만 구성이 크게 바뀐 판이라 단일 바이너리 설정을 이 단계에서 확인하지 못했다. 2.7 부터 OTLP 수신 기본이 localhost → `0.0.0.0:4318` 명시. 매니페스트 Service 에 4318 · 3200, 제어 노드 고정.
17. **스모크 [11] 검색** — `{ span.transfer.id = … } && { resource.service.name = "bank-gateway" }` 로 [3] 의 멱등 재응답 trace(서버 구간 하나)를 거른다. Tempo 검색의 traceID 는 앞 0 이 빠질 수 있어 32자로 채운 뒤 로그를 grep. actuator 구간 0 도 본다.
18. **별도 JVM 게이트웨이의 구간은 테스트의 OTLP 수신기로** — 게이트웨이 JVM 에 주소 인자를 주고 JDK HttpServer + `opentelemetry-proto`(1.10.0-alpha, BOM 밖 — 런타임에 이미 오는 버전으로 고정)로 받는다. 새 흐름 테스트 클래스를 만들지 않고 기존 `HttpGatewayFlowTest` 에 더한다 (새 컨텍스트 = 새 컨테이너). 샘플링 0 테스트만 컨텍스트를 하나 더 띄운다.
19. **exemplar 는 덤 Task 11 로 유지** — Boot 4.1.1 에 Prometheus exemplar 자동 구성이 있다 (앱 코드 없음). Prometheus `--enable-feature=exemplar-storage` · Grafana `exemplarTraceIdDestinations` · 패널 13. 보이지 않으면 되돌린다 (OpenMetrics 수집 확인 단계 포함).
20. **로그 줄 모양** — 실험 도구 · 스모크는 kubectl 시각 열과 부분 문자열만 읽어 상관 id 가 들어가도 그대로다 (점검함, 스펙 C8). Boot 기본 상관 패턴이 traceId 를 찍는지는 Task 3 통합 테스트가 확인하고, 비어 있으면 `logging.pattern.correlation` 을 명시한다.
21. **`reconcile.*` 건수는 숫자(long) 속성** (§5 표) — "우리가 붙이는 속성 값은 문자열" 규칙의 의도된 예외. TraceQL 이 `span.reconcile.republished > 0` 처럼 비교하게 하려는 것이다.
22. **스펙 §8 통합 6(추적 끔에서 기존 흐름 그대로)은 대표 흐름 — 출금 · 1원인증 — 으로 갈음 (전체 스위트를 샘플링 0 으로 다시 돌리지 않음: 전파 코드는 샘플링과 무관하게 같은 길).**
23. **코루틴 컨슈머는 설정 한 줄로 부족했다 (10 을 고침)** — `spring.reactor.context-propagation=auto` 만으로는 trace 가 이어지지 않았다. Spring 7.0.9 의 `PropagationContextElement` 는 Reactor 문맥을 먼저 쓰는데 거기에 소비 구간이 없고, `bank.transfer` 는 `withContext(db)` 밖에서 돈다. 리스너 `on` 본문 전체를 Micrometer `ObservationRegistry.asContextElement()` 로 감싸 해결했다 (Task 7).
24. **JDK HttpClient 판은 CLIENT 구간이어야 한다** — 계획의 코드는 INTERNAL 구간을 냈다. 추가한 `JdkClientPropagationTest` 가 잡았고 `RequestReplySenderContext(setter, Kind.CLIENT)` 로 고쳤다.
25. **E10 을 글자 그대로 지킨다** — 돈 흐름 위의 모든 추적 호출(`Tracer.inSpan` · JDK 관측 · `bank.request` · `TraceTags` · 아웃박스 구간 열기)을 `runCatching` 으로 감싼다 (첫 실패만 WARN, 이후 DEBUG). 업무 블록은 정확히 한 번만 실행된다.
26. **traceparent 끝 플래그는 비교하지 않는다** — OpenTelemetry 1.62 는 W3C 2단계의 "random trace id" 비트를 켜서 `-03` (샘플링 0 이면 `-02`) 이다. `-01` 문자열 비교 코드는 깨진다.
27. **Grafana 익명 보기 사용자가 Explore 를 못 열었다** — `GF_USERS_VIEWERS_CAN_EDIT=true` (kind 만, 저장은 여전히 못 한다).
28. **스모크 [11] 의 검색 · 로그 확인** — Tempo 검색은 시작 · 끝 시각이 필요하고 요청 뒤 약 8초 지나야 보인다(제한된 재시도). `kubectl logs | grep -q` 는 pipefail 아래 SIGPIPE 로 거짓 실패하므로 `grep -c`.
29. **실험 도구 안전장치** — `run.sh` 는 인자를 검사한 **뒤에** 이전 출력을 지운다 (잘못된 인자가 추적되는 원자료를 지웠었다). `TRACING=off` 는 steady 에만. T1d (Tempo 0대) 는 Tempo 의 emptyDir 을 비운다.
30. **실제 422 · 400 요청은 구간에 예외를 싣지 않는다** — `ApiExceptionHandler` 가 처리한다. 지우개는 프로브 구간 테스트(지우개를 빼면 실패함)로 증명한다.
