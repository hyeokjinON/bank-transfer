# ADR-0001 모듈러 모놀리스 + 포트/어댑터로 시작한다

- 상태: 채택 (2026-10-01)

## 맥락
예전에 운영한 시스템은 처음부터 22개 모듈을 각각 별도 프로세스로 띄우고 Kafka 로 연결했다.
은행 회선 장애가 다른 업무로 번지지 않는 장점이 있었지만, 기능 하나를 바꾸려면 여러 모듈을 같이 배포해야 했고,
같은 코드가 은행 수만큼 복사돼 있었다.

## 결정
- 하나의 배포 단위(`apps/api`) 안에서 **Gradle 모듈로 경계를 나눈다**.
- 도메인 모듈(`account`)은 Spring·Netty 를 의존하지 않는다. 은행은 `BankPort` 인터페이스로만 안다.
- 실제 연결(어댑터)은 실행 모듈에서 조립한다.
- 경계는 Gradle 의존성으로 강제된다. `account` 의 build 파일에 Netty 가 없으므로, 도메인 코드에서 Netty 를 import 하면 컴파일이 실패한다.

## 결과
- 도메인 규칙을 가짜 `BankPort` 로 밀리초 단위 테스트할 수 있다.
- P8 에서 게이트웨이를 별도 서비스로 떼어낼 때, `BankPort` 구현만 HTTP/Kafka 클라이언트로 바꾸면 된다.
- 단점: 아직은 모듈 경계를 런타임에 강제하지 않는다. 필요해지면 ArchUnit 테스트를 추가한다.
